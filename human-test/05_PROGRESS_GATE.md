# Human Pilot 01 — Progression Gate

This is a small falsification/usability pilot, not a statistical efficacy study.
The thresholds below are internal operating rules only.

## RED — stop and repair before more recruitment

Any truth/permission hard fail:
- fabricated source or evidence
- inaccessible material represented as read
- unauthorized sensitive login/data/payment action
- materially unsupported decisive claim that survives the normal review path

Also RED when the same core task repeatedly cannot complete without facilitator rescue.

## AMBER — keep candidate isolated and repair narrowly

Examples:
- report delivery regularly needs a second request
- useful research arrives, but turns/questions/reading burden are clearly excessive
- testers cannot explain why they would use FieldPilot instead of normal AI
- source broker adds links but not decision value
- output is trusted only after heavy manual re-checking
- usage burden appears severe but provider/token cause is still UNKNOWN

## GREEN FOR NEXT STAGE — proceed to controlled A/B, not production

For the first 3–4 testers:
- no truth/permission hard fail
- most testers complete TASK A without facilitator rescue
- required report artifact is physically delivered and openable when the host supports artifact creation
- at least two testers can point to a concrete action/decision/source they used, not only say “좋아요”
- at least one new user can explain a meaningful difference from ordinary ChatGPT/Claude
- no repeated severe usage-burden signal comparable to the prior “~3 questions / >90% visible allowance” report

If usage telemetry is not exposed, record UNKNOWN. Do not convert elapsed time, word count, or visible allowance into token savings.

## NEXT STAGE IF GREEN

Run a blinded comparison:
1. freeze one or more unseen cases,
2. compare the current candidate against the chosen baseline under the same host/model/access conditions,
3. hide candidate identity from judges,
4. judge factual/source failures first, then decision usefulness and user effort,
5. preserve all raw outputs before interpretation.
