# NotebookLM CG Omnibus Feedback Analysis Prompt — Compact v4.2

선택된 이번 CG 피드백 강의 소스만 근거로 분석해줘.
다른 날짜 강의, 선택되지 않은 소스, 기존 대화, 외부 지식을 섞지 마.

이 프롬프트는 여러 학생이 서로 다른 캐릭터 제작 단계에서 순차적으로 피드백받는 옴니버스형 수업 전용이다.
학생이 없거나 학생별 진도 추적이 없는 CG 튜토리얼이면 분석을 중단하고 일반 강의 전용 스킬을 사용해야 한다.

## 규칙

1. 학생 이름을 추측하지 않는다. 불확실하면 원문 표기와 `name_status: verify`를 기록한다.
2. 같은 학생이 다시 등장하면 별도 인물로 만들지 말고 재등장 세션으로 연결한다.
3. 개인 작업물에만 해당하는 조언과 공용 원칙을 구분한다.
4. 현재 제작 단계, 문제, 강사의 수정 지시, 완료 기준, 다음 확인 항목을 분리한다.
5. 시간 정보가 없으면 시간을 만들지 않는다.
6. 발췌 번호를 영상 타임스탬프로 해석하지 않는다.
7. 전문용어·도구·수치가 불확실하면 원문과 교정 후보를 함께 적는다.
8. 화면에서만 확인 가능한 수정은 `화면 확인 필요`로 둔다.
9. 강사가 말하지 않은 작업 순서·원인·복구법을 만들지 않는다.
10. 한 강의만으로 `standard`를 부여하지 않는다.

# 1. 강의 정보와 전체 요약
- 과정명, 강의일, 강사, 주요 프로그램
1. 전체 작업 범위
2. 여러 학생에게 반복된 핵심 문제·원칙
3. 다음 작업에서 먼저 확인할 행동

# 2. 학생 세션 전환표
| 순서 | 학생 표기 | name_status | 작업물 | 제작 단계 | 확인된 시작 시각 | 시작 앵커 | 끝 앵커 | 재등장 여부 |

# 3. 학생별 상세 기록
각 학생·세션마다 작성한다.
- 학생 표기와 aliases 후보
- name_status: confirmed | verify
- 동일 학생·재등장 후보
- 작업물과 현재 제작 단계
- 이전 작업·피드백과 반영 여부
- 이번 작업 상태와 핵심 문제
- 강사가 지적한 증상과 직접 설명한 원인
- 강사의 피드백과 수정 순서
- 중간·완료 판단 기준
- 실패 증상, 예방, 복구
- 다음 과제·확인 항목
- 개인 사례 / 공용 원칙 후보
- 시작·끝 앵커와 확인된 시간
- 화면 확인 필요와 불확실한 부분

# 4. 재등장 연결
| 학생 | 이전 세션 | 재등장 세션 | 달라진 점 | 미해결 항목 | 근거 앵커 |

# 5. 캐릭터 제작 단계 후보
다음 11단계 중 확인된 것만 배치한다.
1. 레퍼런스와 기획
2. 블록아웃과 비례
3. 얼굴과 인체 스컬핑
4. 의상과 주름
5. 헤어와 카드
6. 하드서페이스와 장신구
7. 리토폴로지
8. UV와 베이크
9. 텍스처와 재질
10. 리깅 대응
11. 최종 검수

| 내용 | 단계 후보 | 관련 학생·세션 | 배치 근거 | 확실성 |

# 6. 절차·도구·실수·복구
- 실제로 설명된 절차의 목적·선행 조건·순서·완료 기준
- 프로그램·기능·도구·단축키·설정값
- 실수, 증상, 강사가 설명한 원인, 원인 후보, 예방, 복구
- 관련 학생·세션과 근거 앵커
- 화면 확인 필요

# 7. 공용 개념·반복 원칙 후보
각 후보마다 작성한다.
- 개념·원칙명과 한 문장 정의
- 상태: `case` / `recurring 가능성` / `principle 가능성`
- 적용 단계와 조건·예외
- 개인 사례와 분리된 근거
- 관련 학생·세션과 앵커
- 이번 강의 안의 반복 횟수
- 추가 검증 사항

# 8. 근거 부족·검토 대기
- 학생 이름·aliases 불확실
- 동일 학생·재등장 여부 불확실
- 세션 경계·제작 단계 불확실
- 시간 정보 부족
- 전문용어·수치·설정값 불확실
- 화면에서만 확인 가능한 수정
- 과거 원문 또는 다음 강의가 필요한 비교
