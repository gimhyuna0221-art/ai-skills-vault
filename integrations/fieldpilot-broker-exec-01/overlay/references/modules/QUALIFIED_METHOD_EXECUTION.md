# Qualified method reuse, not unconditional large-to-small delegation

Extension broker-exec-01. Use only for reusable-method design, economical execution or escalation. Preserve existing company routing/authority; this is not another controller or a model-switching engine.

## 1. Retrieve before designing

First look for a current method matching the task family, scope, evidence requirements and delivery. A one-off simple job may be cheaper to complete directly. Use a capable designer/reviewer for a new domain, missing method, material conflict, changed scope, failed method, or consequential interpretation. Mechanical discovery/extraction need not all run on the most expensive model.

The designer produces a compact METHOD_CARD: applicability/exclusions; coverage; source roles and discovery/fallback strategy; ordered steps with required inputs/outputs and observable failures; extraction fields; one example/counterexample; tools/permissions; delivery contract; escalation; version/content hash; review date/triggers; qualification evidence and rollback pointer. Do not save private chain-of-thought or a huge planning transcript.

Stable method and volatile facts are different. Current ownership, results, prices, access conditions and market estimates need appropriate fresh evidence. Reuse the way of checking them, not old conclusions. A fixed source winner is not methodology.

## 2. Qualify the executor

Use the least costly model that has actually met this task's quality floor under the matching method hash, model/effort, host, tools and permissions. A strong-model result does not qualify a weaker model. Vendor rank, self-confidence, a checklist or one worked example is not qualification.

Use held-out cases, negative cases and clean-session invocation. Record the evidence, reviewer, hard failures, scope and expiry. Do not issue a qualification solely from the same writer's self-score. If the method changes, invalidate its old qualification. If no qualified economical executor exists, keep an adequate current model or run an authorized bounded qualification; do not silently downgrade.

The skill cannot switch models by itself. With no authorized provider/host dispatch, report SINGLE_HOST and execute with the current adequate model. Do not invent a smaller-model run. New APIs, subscriptions, external input submission and paid execution remain approval-gated. Do not set up an always-on agent team.

## 3. Execute with evidence, then escalate exceptions

Provide the case, matching method, relevant sources and required modules, not the designer's entire conversation. Return findings, exact evidence/artifact pointers, limits and observed resource use. Preserve original evidence across handoffs; repeated summaries are not a substitute for sources.

When new evidence invalidates the plan, sources conflict, fields cannot be established, scope changes or consequential inference is needed, return the affected portion for capable/domain/human review. Do not blindly finish an obsolete plan. Deterministic calculations, schema checks, deduplication and rendering belong in scripts when suitable. Scripts cannot verify semantic truth from a PASS label.

broker_control.py checks declared scope, capabilities, method hash, qualification evidence-file integrity and physical artifacts. It does not independently authenticate evaluation records, decide source truth, infer risk correctly, find the best site, invoke an API or switch models. The trusted controller must audit the recorded evidence and complete semantic QA.

## 4. Qualify the improvement, not only the recipe

Compare latest baseline vs broker extension with the SAME model before evaluating an economical executor. Then compare the SAME method across actual runtime profiles. Where supported, include direct specialist-service/source use; do not punish a service for functions it does not claim. Keep rights/access/input conditions comparable.

Separate design cases from evaluation cases. SK hynix/TIO examples already used to develop this extension are regression material, not independent holdouts. Do not open previously sealed mappings or repurpose old verdicts. Freeze the candidate and evaluate clean sessions without coaching. Screen material factual, citation, coverage, permission and delivery regressions before cost.

Measure design + execution + review + escalation + user correction, not just the cheap model call. Preserve unknown costs. Output length/file bytes do not prove tokens or subscription quota saved. Do not mix API money with subscription allowances.

Same-unit decision formula: D/N + E + V + pR < H. D=method design, N=reuses, E=execution, V=review, pR=expected escalation, H=direct capable execution. This is algebra, not measured savings. Small N, many exceptions or high review cost may make a single model preferable.

Promote only within observed task/model/host scope under existing authority. Retain rollback. Existing rc04 behavioral/approval debt remains; new control-code tests do not close G1-G6 or prove research superiority.
