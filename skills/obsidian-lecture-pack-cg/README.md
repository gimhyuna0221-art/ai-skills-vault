# Obsidian Lecture Pack — CG Omnibus

여러 학생이 서로 다른 캐릭터 제작 단계에서 순차적으로 피드백받는
CG 옴니버스 수업 전용 독립 스킬입니다.

현재 버전: `4.3.0`  
상태: `stable draft`

## 사용 대상

- 학생별 작업물과 제작 단계가 다름
- 강사가 학생을 순서대로 피드백함
- 같은 학생이 강의 중 또는 다음 강의에 다시 등장함
- 이전 피드백 반영 여부와 현재 제작 단계를 이어서 추적해야 함
- 날짜별 강의 기록과 반·학생별 이력을 보존해야 함
- 여러 강의의 본질을 캐릭터 제작 11단계 워크플로우로 통합해야 함

학생이 없거나 학생별 진도 추적이 없는 CG 튜토리얼은
일반 `obsidian-lecture-pack`을 사용합니다.

## v4.3 핵심 구조

```text
강의
→ 날짜별 원문·북마크·최종노트 보존

학생 사례
→ 반·학생별 날짜 진행 이력 보존

개념
→ 여러 학생과 강의에서 재사용되는 지식 통합

캐릭터 워크플로우
→ 날짜와 학생을 본문에서 제거하고
  현재까지 확인된 최종 절차로 재작성
```

워크플로우 파일 끝에 `YYYY-MM-DD 강의 반영` 섹션만 추가하는 방식은
정식 병합으로 인정하지 않습니다.

사용자가 `/obsidianpack`을 입력했더라도 다음 조건이 명확하면

- 여러 학생의 CG 작업을 순차 피드백
- CG 전용 동기화팩 첨부
- 학생 이력과 11단계 워크플로우 누적 필요

## NotebookLM 프롬프트

```text
prompts/notebooklm-cg-omnibus-feedback.md
```

일반 강의 프롬프트와 혼합하지 않습니다.

## 매주 필요한 입력

1. 최신 `00_매주_ChatGPT에_보낼_AI동기화팩.zip`
2. 이번 SBV/SRT/VTT 또는 YouTube 시간 표시 스크립트
3. 이번 NotebookLM CG 옴니버스 분석본
4. YouTube URL
5. 강의 날짜·과정명·강사명
6. 요일 또는 반 이름 `class_group`
7. 선택 이미지
8. 정확한 과거 비교가 필요할 때만 해당 날짜의 원문전사

`class_group`이 없으면 추측하지 않고 `unknown`으로 기록합니다.

## 학생 식별

학생 식별 우선순위:

1. 안정적 `student_id`
2. `class_group + 확인된 이름`
3. aliases·작업물·이전 세션 근거

병합 규칙:

- 같은 이름 + 같은 반 → 기존 학생 이력에 날짜 추가
- 같은 이름 + 다른 반 → 별도 학생으로 생성
- 반 이동 가능성 → 사용자 확인 전 자동 병합 금지
- 이름 또는 반 불확실 → 검토 대기

## 매주 처리 흐름

```text
지난 최신 CG 동기화팩
+ 이번 자막·NotebookLM 분석·YouTube URL·반 정보
→ 학생 세션·재등장·동명이인 검증
→ 날짜별 강의 기록 생성
→ 학생별 이력 갱신
→ 공용 개념 병합
→ 관련 워크플로우 기존 본문 재검토·최종 통합
→ 전체 파이프라인·인덱스·로그·지식 간극 갱신
→ 다음 처리용 CG 동기화팩 완전 재생성
→ 결과 ZIP 생성·무결성 검사
```

## 워크플로우 통합 상태

새 강의의 각 후보는 다음 중 하나로 분류합니다.

- `body_integrated`: 기존 본문을 보강하거나 재작성
- `evidence_only`: 본문은 유지하고 근거만 추가
- `candidate_pending`: 근거 부족으로 검증 후보 보류
- `no_change`: 해당 단계에 새 정보 없음

워크플로우 본문은 가능한 범위에서 다음 구조를 유지합니다.

- 현재 확인된 핵심
- 목적
- 시작 전 조건
- 방식 선택 기준
- 작업 순서
- 중간 판단 기준
- 완료 판단 기준
- 실패 증상·원인
- 예방·복구
- 적용 조건·예외
- 관련 개념
- 학생 사례
- 근거 이력
- 검토 필요

## 핵심 산출물

- 날짜별 강의 기록
- 반·학생별 진행 이력과 재등장 연결
- 공용 개념
- 최종 통합된 캐릭터 제작 11단계 워크플로우
- 강의 인덱스와 소스 인덱스
- 병합 로그와 지식 간극
- 완전 재생성된 AI 동기화팩
- `옵시디언_CG_주간업데이트.zip`

## 사용자 전달 구조

```text
옵시디언_CG_주간업데이트.zip
├─ 새 강의와 갱신된 학생·개념·워크플로우 파일
├─ 갱신된 인덱스·검토 대기·병합 로그
└─ 00_매주_ChatGPT에_보낼_AI동기화팩.zip
```

기존 `캐릭터_모델링` 폴더를 삭제하지 않습니다.
결과 ZIP을 저장소 최상단에 병합하고 같은 경로의 누적 파일만 덮어씁니다.

## CG 동기화팩

매 병합 후 부분 수정하지 않고 완전 재생성합니다.

포함:

- AI 허브, 과정목차, 강의 인덱스
- 소스 인덱스, 지식 간극, 병합 로그
- 학생 사례 전체
- 개념 전체
- 최종 통합된 캐릭터 워크플로우 전체
- 모든 강의의 목차·북마크·최종노트
- 현재 CG SKILL, manifest, CG NotebookLM 프롬프트
- 파일 목록과 SHA-256 manifest

제외:

- 모든 과거 원문전사
- 원본 자막·이미지·영상
- NotebookLM 원본
- 검사·임시 파일과 `.obsidian`

## 완료 원자성

필수 입력 검증을 통과했다면 다음 중 하나로 반드시 종료합니다.

1. 결과 ZIP 생성·무결성 검사·파일 링크 제공
2. 작업을 막는 구체적인 오류 보고

분석만 수행하고 결과물 없이 종료하는 상태는 완료로 인정하지 않습니다.

## 현재 검증 상태

확인 완료:

- 일반 강의 스킬과 분리
- 날짜별 강의 보존
- 반·학생별 식별 규칙
- 11단계 워크플로우 본문 최종 통합 규칙
- 날짜별 섹션 추가만으로 완료 처리하지 않는 검사
- 동기화팩 완전 재생성
- 결과 ZIP 생성 전 완료 보고 금지
- 기존 저장소 삭제 없이 폴더 병합

추가 반복 검증 필요:

- 동일 학생 재등장과 aliases 연결
- 다른 반의 동명이인 분리
- 실제 강의 3회 이상 누적 후 지식 성숙도 승격
- 충돌하는 피드백의 조건별 분기
