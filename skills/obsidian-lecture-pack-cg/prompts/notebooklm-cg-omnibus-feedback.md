# NotebookLM CG Omnibus Feedback Analysis Prompt — Compact v4.3

선택된 이번 CG 피드백 강의 소스만 근거로 분석해줘.
다른 날짜 강의, 선택되지 않은 소스, 기존 대화, 외부 지식을 섞지 마.

이 프롬프트는 여러 학생이 서로 다른 캐릭터 제작 단계에서 순차적으로 피드백받는 옴니버스형 수업 전용이다.

## 규칙

1. 학생 이름과 반을 추측하지 않는다.
2. 불확실하면 `name_status: verify`, `class_status: verify`를 기록한다.
3. 같은 학생의 재등장과 동명이인 가능성을 분리한다.
4. 개인 작업물 조언과 다른 캐릭터에도 적용 가능한 내용을 구분한다.
5. 시간 정보가 없으면 만들지 않는다.
6. 발췌 번호를 영상 타임스탬프로 해석하지 않는다.
7. 강사가 말하지 않은 순서·원인·복구법을 만들지 않는다.
8. 화면에서만 확인 가능한 내용은 `화면 확인 필요`로 둔다.
9. 한 사례만으로 `standard`를 부여하지 않는다.
10. 워크플로우 후보는 학생 이름과 날짜를 제거해도 성립하는 문장으로 작성한다.

# 3. 학생별 상세 기록

각 학생·세션마다 작성한다.

- 반과 학생 표기
- aliases 후보
- name_status / class_status
- 동일 학생·동명이인·재등장 후보
- 작업물과 현재 제작 단계
- 이전 피드백과 반영 여부
- 이번 문제와 강사의 직접 설명
- 수정 순서
- 중간·완료 판단 기준
- 실패 증상·원인·예방·복구
- 다음 과제
- 개인 사례 / 공용 개념 후보 / 워크플로우 후보
- 시작·끝 앵커와 시간
- 화면 확인 필요

# 6. 절차·도구·실수·복구

- 실제로 설명된 목적·선행 조건·순서·완료 기준
- 프로그램·기능·도구·단축키·설정값
- 실수·증상·강사가 설명한 원인·예방·복구
- 관련 학생·세션과 근거 앵커
- 화면 확인 필요

# 7. 공용 개념 후보

각 후보마다 작성한다.

- 개념명과 한 문장 정의
- 상태: case / recurring 가능성 / principle 가능성
- 적용 단계와 조건·예외
- 개인 사례와 분리된 근거
- 관련 학생·세션과 앵커
- 반복 횟수
- 추가 검증 사항

# 8. 워크플로우 통합 후보

학생 이름과 날짜를 제거해도 성립하는 문장만 작성한다.

각 후보마다:

- 대상 제작 단계
- 삽입할 본문 섹션:
  - 현재 확인된 핵심
  - 목적
  - 시작 전 조건
  - 방식 선택 기준
  - 작업 순서
  - 중간 판단 기준
  - 완료 판단 기준
  - 실패 증상
  - 원인
  - 예방
  - 복구
  - 적용 조건과 예외
- 통합 문장
- 적용 조건
- 예외
- 근거 학생·세션·앵커
- 이번 강의 안 반복 횟수
- 상태 후보:
  - body_integrated 가능성
  - evidence_only 가능성
  - candidate_pending

기존 워크플로우와의 실제 비교·최종 병합은 ChatGPT가 동기화팩을 읽고 수행한다.

# 9. 근거 부족·검토 대기

- 학생 이름·반 불확실
- 동일 학생·동명이인 불확실
- 세션 경계·제작 단계 불확실
- 시간 정보 부족
- 전문용어·수치·설정값 불확실
- 화면에서만 확인 가능한 수정
- 과거 원문 또는 다음 강의가 필요한 비교
