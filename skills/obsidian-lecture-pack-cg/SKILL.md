# Obsidian Lecture Pack — CG Omnibus v4.3

## 역할과 경계

이 스킬은 여러 학생이 서로 다른 캐릭터 제작 단계에서 순차적으로 피드백받는 옴니버스형 수업 전용이다.

분석 단위:

- 강의 날짜와 반·요일
- 학생, 작업물, 현재 제작 단계
- 이전 피드백과 반영 여부
- 피드백 세션과 재등장 세션
- 수정 순서, 판단 기준, 완료 기준, 다음 확인
- 개인 사례와 공용 원칙
- 기존 워크플로우 본문에 통합할 본질

학생이 없거나 학생별 진도 추적이 없는 CG 튜토리얼은 독립 스킬 `obsidian-lecture-pack`으로 넘긴다.

NotebookLM에는 `08_NotebookLM_CG옴니버스_프롬프트_v4.3.md`만 사용한다.

## 최종 목표

```text
매주 CG 옴니버스 수업
→ 날짜별 검증 강의 기록
→ 반·학생별 진행 이력
→ 공용 개념
→ 날짜와 학생을 제거한 최종 11단계 워크플로우
→ 근거·앵커·타임스탬프가 있는 제2의 뇌
```

공식 지식베이스 폴더명은 `캐릭터_모델링`이다.
기존 경로·사용자 문장·안정적 ID를 임의 변경하지 않는다.

## 명령

- `/obsidian-cg` 또는 `/obsidianpack-cg`: 이번 강의 검증·증분 병합
- `/obsidian-cg-full`: 원본·검사자료까지 확장 전달
- `/obsidian-cg-sync-rebuild`: 실제 최신 저장소에서 동기화팩 완전 재생성
- `/obsidian-cg-lint`: 링크·ID·중복·학생·워크플로우 통합 상태 검사
- `/obsidian-cg-query`: 근거와 함께 지식베이스 질의

명령이 `/obsidianpack`이어도 명백한 CG 다인 피드백 형식이고 CG 동기화팩이 첨부되면 CG로 자동 라우팅하고 이를 보고한다.

## 기본 입력

1. 최신 `00_매주_ChatGPT에_보낼_AI동기화팩.zip`
2. 이번 SBV/SRT/VTT 또는 시간 표시 스크립트
3. 이번 NotebookLM CG 분석본
4. YouTube URL
5. 강의 날짜·강사·과정명
6. 요일 또는 반 이름 `class_group`
7. 선택 이미지
8. 정확한 과거 비교가 필요할 때만 특정 원문전사

`class_group`이 없으면 추측하지 않고 `unknown`으로 둔다.

동기화팩이 없으면 현재 강의만으로 초기화할 수 있지만 과거와 누적 병합했다고 주장하지 않는다.
manifest가 손상되거나 일반 강의용 동기화팩이면 병합을 중단한다.

## 지식 계층의 역할

### 1. 강의

`강의/YYYY-MM-DD 강의명/` 아래에 날짜별 사실을 보존한다.

- `00_강의목차.md`
- `01_원문전사.md`
- `02_북마크.md`
- `03_최종노트.md`

과거 강의는 새 강의로 대체하지 않는다.

### 2. 학생 사례

학생별 날짜 진행 이력을 누적한다.

학생 식별 우선순위:

1. 안정적 student_id
2. `class_group + 확인된 이름`
3. aliases와 작업물·이전 세션 근거

규칙:

- 같은 이름 + 같은 반 → 기존 학생 이력에 날짜 추가
- 같은 이름 + 다른 반 → 별도 학생으로 생성
- 반 이동 가능성 → 사용자 확인 전 자동 병합 금지
- 이름 또는 반이 불확실 → `name_status: verify`, `class_status: verify`
- 동명이인 충돌 시 파일명에 반을 붙여 구분하되 기존 유일 학생 경로는 유지

### 3. 공용 개념

날짜와 학생을 넘어 재사용되는 도구·원리·실수·복구법을 통합한다.
같은 의미의 개념은 새 파일을 만들지 않고 근거를 추가한다.

### 4. 캐릭터 워크플로우

워크플로우는 강의 일지가 아니라 **현재까지 확인된 최종 작업 절차**다.

날짜·학생별 문장을 본문 끝에 계속 추가하지 않는다.
새 근거가 들어오면 기존 본문을 비교·재작성하여 하나의 최신 절차로 통합한다.

## 캐릭터 제작 단계

1. 레퍼런스와 기획
2. 블록아웃과 비례
3. 얼굴과 인체 스컬핑
4. 의상과 주름
5. 헤어와 카드
6. 하드서페이스와 장신구
7. 리토폴로지
8. UV와 베이크
9. 텍스처와 재질
10. 리깅 대응
11. 최종 검수

강의에서 다루지 않은 단계를 억지로 채우지 않는다.

## 처리 절차

1. 동기화팩 manifest·버전·파일 목록·SHA-256을 검사한다.
2. 자막 인코딩·시간·전체 길이를 확인한다.
3. NotebookLM 앵커와 원문을 대조한다.
4. 강의 날짜·반·학생 이름·세션 경계·재등장을 검증한다.
5. 북마크 시작 시각과 YouTube `t=` 초를 계산한다.
6. 개인 피드백과 공용 개념·워크플로우 후보를 분리한다.
7. 기존 학생·개념·워크플로우와 의미 중복·충돌을 검사한다.
8. 강의 폴더를 날짜별 독립 기록으로 생성한다.
9. 학생 사례에 날짜별 세션을 추가한다.
10. 공용 개념을 병합한다.
11. 관련 11단계 워크플로우의 **기존 본문을 최종 통합 형태로 재작성**한다.
12. `00_전체 파이프라인.md`의 근거·성숙도·단계 상태를 갱신한다.
13. 강의·소스 인덱스, 병합 로그, 지식 간극을 갱신한다.
14. AI 동기화팩을 완전 재생성한다.
15. 오류 수정 후 링크·ID·manifest·워크플로우 통합 상태를 재검사한다.
16. 결과 ZIP을 실제 생성하고 무결성을 검사한 뒤 완료 보고한다.

각 단계 문서는 가능한 범위에서 다음 구조를 유지한다.

```text

작업 순서

```

근거가 없는 항목은 만들어 채우지 않는다.
확인되지 않은 항목은 `근거 부족`으로 남긴다.

## 워크플로우 통합 알고리즘

새 강의에서 추출한 각 항목을 다음 순서로 처리한다.

1. 학생 고유 조언인지, 다른 작업에도 적용 가능한지 판정한다.
2. 적용 가능한 제작 단계와 본문 섹션을 지정한다.
3. 기존 본문과 의미가 같은지, 보강하는지, 충돌하는지 비교한다.
4. 결과를 다음 중 하나로 분류한다.

- `body_integrated`: 기존 본문을 보강·재작성
- `evidence_only`: 본문은 이미 충분하여 근거만 추가
- `candidate_pending`: 한 사례뿐이거나 조건 불명확으로 검증 후보 보류
- `no_change`: 새 워크플로우 정보 없음

5. `body_integrated`는 날짜·학생 표현을 제거하여 일반 절차로 재작성한다.
6. 학생·날짜·타임스탬프는 `근거 이력`에만 남긴다.
7. 충돌하는 지시는 조건별 분기로 통합하거나 지식 간극으로 이동한다.
8. 동일 문장을 날짜별 섹션으로 중복 추가하지 않는다.
9. 기존에 틀린 내용이 아니라면 삭제하지 말고 더 정확한 구조로 흡수한다.
10. 한 사례만으로 보편 절차처럼 단정하지 않는다.

## 워크플로우 병합 완료 기준

다음 조건을 모두 만족해야 완료다.

- 새 강의가 관련 제작 단계에 배치됨
- 기존 본문의 핵심·순서·판단·실패·복구가 재검토됨
- 새 정보가 있으면 본문이 실제 수정되었거나 `candidate_pending` 이유가 기록됨
- 날짜별 `YYYY-MM-DD 강의 반영` 섹션만 추가하고 끝내지 않음
- 근거 이력에 강의·학생·북마크 링크가 추가됨
- `00_전체 파이프라인.md`에 최신 강의 근거가 포함됨
- 완료 보고에 본문 통합·근거 추가·변경 없음 수가 구분됨

워크플로우 파일 끝에 날짜 섹션을 붙이는 것만으로는 완료가 아니다.

## 지식 성숙도

```text
case → recurring → principle → standard
```

- `case`: 한 사례
- `recurring`: 서로 다른 강의·학생에서 반복
- `principle`: 적용 조건을 포함한 일반 원칙
- `standard`: 순서·판단·예외·복구까지 충분히 확인

승격할 때 근거 강의 수와 학생 수를 확인한다.

## AI 동기화팩

매 병합 후 완전 재생성한다.

포함:

- AI 허브·과정 목차·강의 인덱스
- 소스 인덱스·지식 간극·병합 로그
- 학생 사례 전체
- 개념 전체
- **최종 통합된 캐릭터 워크플로우 전체**
- 모든 강의의 목차·북마크·최종노트
- 최신 CG SKILL·manifest·NotebookLM 프롬프트
- 파일 목록과 SHA-256 manifest

제외:

- 모든 과거 원문전사
- 원본 자막·이미지·영상
- NotebookLM 원본
- 검사·임시 파일·`.obsidian`

## 사용자 전달

```text
옵시디언_CG_주간업데이트.zip
```

ZIP은 저장소 상대 경로를 유지한다.
사용자는 기존 저장소 폴더를 삭제하지 않고 내용물을 병합하며, 같은 경로의 누적 파일만 덮어쓴다.

## 품질검사

- 깨진·모호한 내부 링크
- 중복 ID·유사 개념
- 학생 이름·class_group·aliases 충돌
- 재등장 연결 누락
- 개인 사례의 과잉 일반화
- 워크플로우 날짜 섹션만 추가된 미통합 상태
- 본문 수정 없이 `워크플로우 갱신 완료`로 보고한 항목
- 근거 없이 `standard`가 된 항목
- `00_전체 파이프라인`의 최신 강의 근거 누락
- 시간값·앵커·YouTube 초 계산
- 동기화 manifest·해시 불일치
- 일반 강의 프롬프트 혼입
