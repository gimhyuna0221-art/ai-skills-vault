# NotebookLM General Lecture Analysis Prompt

선택된 이번 강의 소스 1개만 근거로 분석해줘.
다른 날짜의 강의, 선택되지 않은 소스, 외부 지식을 섞지 마.

## 강의 정보

- 과정명: [과정명]
- 강의일: [YYYY-MM-DD]
- 강사: [강사명]
- 분야·도메인: [분야]
- 강의 형식: [설명형 / 옴니버스 피드백 / 실습 / 질의응답 / 혼합]
- 주요 분석 단위: [학생 / 사례 / 작업물 / 주제 / 챕터 / 문제]
- 도메인 작업 단계 목록: [단계 목록 또는 미입력]

## 최종 목적

이 분석은 자막 또는 원문과 대조한 뒤 Obsidian의 다음 네 층에 누적한다.

1. 강의 기록
2. 세션·사례별 기록
3. 공용 개념
4. 해당 분야의 단계별 워크플로우

## 중요 규칙

1. 선택된 강의 소스에서 확인되지 않은 정보는 추측하지 않는다.
2. 외부 지식으로 강의 내용을 보충하지 않는다.
3. 정확한 시간 정보가 없으면 타임스탬프를 만들지 않는다.
4. 각 세션이나 주제 구간의 시작·끝 앵커 문장을 원문 그대로 5~15어절 적는다.
5. 사람 이름, 대상명, 전문용어가 불확실하면 후보와 불확실성을 표시한다.
6. 같은 사람·사례·주제가 여러 번 등장하면 각각 별도 세션으로 기록하되 동일 대상 후보임을 표시한다.
7. 특정 사례에만 해당하는 수정과 다른 상황에도 적용 가능한 원칙을 분리한다.
8. 도메인 작업 단계 목록이 제공되면 해당 목록을 사용한다.
9. 단계 목록이 없으면 강의에서 확인되는 단계 후보만 제안하고 확정하지 않는다.
10. 단축키·설정값·수치·도구명이 불확실하면 `불확실`로 표시한다.
11. 화면으로만 확인 가능한 조작이나 결과는 `화면 확인 필요`로 표시한다.
12. 음성인식 오류로 보이는 용어는 원문과 교정 후보를 함께 적는다.
13. 옴니버스형 강의가 아니라면 학생을 만들지 말고 주제·챕터·사례 단위로 구분한다.
14. 해당 내용이 없는 항목은 억지로 채우지 말고 `확인되지 않음`으로 표시한다.
15. 일반화 후보마다 근거가 된 세션이나 앵커를 연결한다.
16. 이번 강의 한 편만으로 원칙이나 절차를 `standard`라고 확정하지 않는다.

다음 Markdown 구조로 출력해줘.

# 1. 세 문장 요약

강의의 목적, 핵심 내용, 다음 행동을 각각 한 문장으로 요약한다.

# 2. 세션·주제 전환표

| 순서 | 세션·대상 | 유형 | 명칭 확실성 | 현재 단계 | 주제 | 시작 앵커 | 끝 앵커 |
|---|---|---|---|---|---|---|---|

`유형`은 학생, 사례, 작업물, 주제, 챕터, 질의응답 중 적절한 것으로 표시한다.

# 3. 세션별 상세 기록

각 세션마다 다음 항목을 작성한다.

- 세션·대상
- 유형
- 현재 단계
- 이전 내용 또는 선행 상태
- 이번 문제·질문·주제
- 강사의 설명·피드백
- 다음 행동 또는 과제
- 관련 기술·개념
- 특정 사례인지 일반화 후보인지
- 근거가 된 시작·끝 앵커 문장
- 불확실하거나 화면 확인이 필요한 부분

# 4. 도메인 워크플로우 단계 후보

강의 내용을 제공된 작업 단계 목록에 배치한다.

작업 단계 목록이 제공되지 않았다면 다음 형식으로 후보를 제안한다.

| 순서 | 단계 후보 | 목적 | 근거 세션 | 확실성 |
|---|---|---|---|---|

강의에서 확인되지 않은 단계를 임의로 추가하지 않는다.

# 5. 단계별 작업 절차

각 절차마다 다음 항목을 작성한다.

- 절차명
- 목적
- 적용 단계
- 선행 조건
- 실제 순서
- 완료 판단 기준
- 실패 증상
- 가능한 원인
- 예방
- 복구
- 근거 세션·앵커
- 확실성

설명되지 않은 세부 절차는 추측하지 않는다.

# 6. 기능·도구·단축키·설정값

| 명칭 | 분류 | 용도 | 사용 상황 | 수치·설정 | 확실성 | 화면 확인 필요 |
|---|---|---|---|---|---|---|

`분류`는 기능, 도구, 단축키, 설정, 재료, 장비, 소프트웨어 중 적절한 것으로 표시한다.

# 7. 반복 원칙 후보

각 항목에 다음 상태 중 하나를 붙인다.

- `case`: 특정 사례에만 적용
- `recurring 가능성`: 다른 세션에서도 반복될 가능성이 있음
- `principle 가능성`: 여러 상황에 적용 가능한 판단 원칙 후보

각 원칙마다 다음을 기록한다.

- 원칙 후보
- 상태
- 적용 조건
- 예외
- 근거 세션
- 근거 앵커
- 추가 검증 필요 사항

# 8. 공용 개념 노트 후보

다음 기준으로 A/B/C를 분류한다.

- A: 이번 강의 안에서 여러 세션에 반복 등장했거나 강사가 일반 원칙이라고 명시한 내용
- B: 한 세션에서만 등장했지만 설명이 명확하고 다른 사례에도 적용 가능한 절차·판단 기준·복구법
- C: 특정 사례에만 해당하거나 근거 부족, 화면 확인 필요, 일반화하기 어려운 내용

A와 B만 독립 개념 노트 후보로 제안한다.
C는 세션별 사례 기록에 남긴다.

각 후보마다 다음을 작성한다.

- 개념명
- 등급
- 한 문장 정의
- 적용 상황
- 관련 절차
- 관련 실수
- 근거 세션·앵커
- 추가 검증 사항

이번 한 강의만으로 A 또는 B를 `standard`라고 확정하지 않는다.

# 9. 실수·복구 표

| 실수 | 증상 | 원인 | 예방 | 복구 | 적용 범위 | 근거 |
|---|---|---|---|---|---|---|

# 10. 화면 확인 필요 구간

각 항목마다 다음을 작성한다.

- 확인할 내용
- 관련 세션
- 원문 앵커
- 화면에서 확인해야 하는 이유
- 확인 후 기록할 항목

# 11. 용어 교정 후보

| 원문 표기 | 교정 후보 | 문맥 | 확실성 | 추가 확인 방법 |
|---|---|---|---|---|

원문을 삭제하거나 교정 후보로 덮어쓰지 않는다.

# 12. 직접 따라 할 체크리스트

강의 내용을 처음부터 실행하는 순서로 작성한다.

- [ ] 선행 준비
- [ ] 실제 작업
- [ ] 중간 확인
- [ ] 완료 검수
- [ ] 오류 발생 시 복구

강의에서 설명되지 않은 단계를 추가하지 않는다.

# 13. 복습 질문

다음 유형을 구분해 작성한다.

- 사실 확인 질문
- 절차 순서 질문
- 원인·결과 질문
- 사례 적용 질문
- 실수 복구 질문

# 14. 근거 부족·추가 확인

다음 항목을 모아서 기록한다.

- 이름 또는 대상 불확실
- 작업 단계 불확실
- 전문용어 불확실
- 수치·설정값 불확실
- 화면 확인 필요
- 원문만으로 판단할 수 없는 내용
- 다음 강의 또는 다른 자료에서 재검증할 내용
