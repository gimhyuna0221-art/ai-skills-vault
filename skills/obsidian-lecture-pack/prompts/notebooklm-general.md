# NotebookLM General Lecture Analysis Prompt

선택된 이번 강의 소스만 근거로 분석해줘.
다른 날짜의 강의, 선택되지 않은 소스, 외부 지식을 섞지 마.

이 프롬프트는 학생별 피드백 수업이 아닌 일반 설명형·실습형·주제형 강의용이다.
학생, 수강생별 진도, 이전 피드백, 학생별 과제를 임의로 만들지 마.

CG 캐릭터 모델링처럼 여러 학생이 서로 다른 작업 단계에서 피드백을 받는 수업은
이 프롬프트가 아니라 `notebooklm-cg-omnibus-feedback.md`를 사용한다.

## 강의 정보

- 과정명: [과정명]
- 강의일: [YYYY-MM-DD]
- 강사: [강사명]
- 분야·도메인: [분야]
- 강의 형식: [설명형 / 실습형 / 사례 분석 / 질의응답 / 혼합]
- 주요 분석 단위: [주제 / 챕터 / 개념 / 사례 / 절차 / 실습 / 문제]
- 도메인 작업 단계 목록: [단계 목록 또는 미입력]

## 최종 목적

이 분석은 자막 또는 원문과 대조한 뒤 Obsidian의 다음 네 층에 누적한다.

1. 강의 기록
2. 주제·챕터별 기록
3. 공용 개념
4. 해당 분야의 단계별 워크플로우

## 중요 규칙

1. 선택된 강의 소스에서 확인되지 않은 정보는 추측하지 않는다.
2. 외부 지식으로 강의 내용을 보충하지 않는다.
3. 학생이 등장하지 않는 일반 강의에서는 학생·진도·이전 피드백 항목을 만들지 않는다.
4. 강의는 주제, 챕터, 개념, 사례, 절차, 실습, 질의응답 단위로 구분한다.
5. 정확한 시간 정보가 소스에 있으면 그 시간만 사용한다.
6. 시간 정보가 없으면 타임스탬프를 만들지 않는다.
7. 각 주제 구간의 시작·끝 앵커 문장을 원문 그대로 5~15어절 적는다.
8. 동일한 개념이 여러 구간에서 반복되면 각각 기록하되 동일 개념 후보임을 표시한다.
9. 강사의 직접 설명, 사례, 비유, 화면 예시, AI의 분석 후보를 구분한다.
10. 특정 사례에만 해당하는 설명과 다른 상황에도 적용 가능한 원칙을 분리한다.
11. 도메인 작업 단계 목록이 제공되면 해당 목록을 사용한다.
12. 단계 목록이 없으면 강의에서 확인되는 단계 후보만 제안하고 확정하지 않는다.
13. 단축키·설정값·수치·도구명이 불확실하면 `불확실`로 표시한다.
14. 화면으로만 확인 가능한 조작이나 결과는 `화면 확인 필요`로 표시한다.
15. 음성인식 오류로 보이는 용어는 원문과 교정 후보를 함께 적는다.
16. 해당 내용이 없는 항목은 억지로 채우지 말고 `확인되지 않음`으로 표시한다.
17. 일반화 후보마다 근거가 된 주제와 앵커를 연결한다.
18. 이번 강의 한 편만으로 원칙이나 절차를 `standard`라고 확정하지 않는다.
19. 강사가 말하지 않은 선행 조건, 원인, 예외, 복구법을 임의로 추가하지 않는다.
20. YouTube 챕터 제목과 실제 발화 문장을 구분한다.

다음 Markdown 구조로 출력해줘.

# 1. 세 문장 요약

다음 세 문장을 각각 작성한다.

1. 이 강의가 해결하려는 문제
2. 강의의 핵심 주장
3. 시청자가 바로 실행할 다음 행동

# 2. 강의 구조 개요

- 강의 전체 목적
- 핵심 질문
- 전개 방식
- 주요 챕터 수
- 실습 또는 사례 유무
- 질의응답 유무
- 화면 확인 필요 여부

# 3. 주제·챕터 전환표

| 순서 | 유형 | 주제·챕터명 | 목적 | 핵심 주장 | 확인된 시작 시각 | 시작 앵커 | 끝 앵커 |
|---|---|---|---|---|---|---|---|

`유형`은 다음 중 적절한 것으로 표시한다.

- 주제
- 챕터
- 개념
- 사례
- 예시
- 절차
- 실습
- 질의응답
- 결론

시간 정보가 없으면 `확인되지 않음`으로 표시한다.

# 4. 주제·챕터별 상세 기록

각 주제마다 다음 항목을 작성한다.

## [주제명]

- 유형:
- 이 구간의 목적:
- 핵심 질문:
- 핵심 주장:
- 강사의 설명:
- 사용한 근거·비유·예시:
- 적용 상황:
- 선행 조건:
- 예외·주의점:
- 실행 절차:
- 기대 결과:
- 화면 확인 필요:
- 시작 앵커:
- 끝 앵커:
- 확인된 시작 시각:
- 불확실한 부분:

강의에서 설명되지 않은 항목은 `확인되지 않음`으로 표시한다.

# 5. 핵심 주장과 근거

| 핵심 주장 | 근거 유형 | 근거 내용 | 관련 주제 | 앵커 | 확실성 |
|---|---|---|---|---|---|

`근거 유형`은 다음 중 적절한 것으로 표시한다.

- 직접 설명
- 사례
- 예시
- 비교
- 비유
- 실습 결과
- 화면 자료
- 질의응답
- 분석 후보

# 6. 개념 관계

강의에 등장한 개념 사이의 관계를 정리한다.

각 관계는 다음 형식으로 작성한다.

- 개념 A:
- 관계 유형: 선행 / 포함 / 대조 / 원인 / 결과 / 예외 / 적용
- 개념 B:
- 관계 설명:
- 근거 주제·앵커:
- 확실성:

강의에서 확인되지 않은 관계는 만들지 않는다.

# 7. 도메인 워크플로우 단계 후보

강의 내용을 제공된 작업 단계 목록에 배치한다.

작업 단계 목록이 제공되지 않았다면 다음 형식으로 후보를 제안한다.

| 순서 | 단계 후보 | 목적 | 입력 | 핵심 행동 | 완료 판단 기준 | 근거 주제 | 확실성 |
|---|---|---|---|---|---|---|---|

강의에서 확인되지 않은 단계를 임의로 추가하지 않는다.

# 8. 단계별 작업 절차

각 절차마다 다음 항목을 작성한다.

- 절차명
- 목적
- 적용 단계
- 선행 조건
- 입력
- 실제 순서
- 중간 확인 기준
- 완료 판단 기준
- 실패 증상
- 강의에서 설명한 원인
- 예방
- 강의에서 설명한 복구
- 근거 주제·앵커
- 확실성

설명되지 않은 세부 절차는 추측하지 않는다.

# 9. 기능·도구·단축키·설정값

| 명칭 | 분류 | 용도 | 사용 상황 | 수치·설정 | 확실성 | 화면 확인 필요 |
|---|---|---|---|---|---|---|

`분류`는 기능, 도구, 단축키, 설정, 재료, 장비, 소프트웨어 중 적절한 것으로 표시한다.

# 10. 반복 원칙 후보

각 항목에 다음 상태 중 하나를 붙인다.

- `case`: 특정 사례에만 적용
- `recurring 가능성`: 다른 사례에서도 반복될 가능성이 있음
- `principle 가능성`: 여러 상황에 적용 가능한 판단 원칙 후보

각 원칙마다 다음을 기록한다.

- 원칙 후보
- 상태
- 적용 조건
- 예외
- 근거 주제
- 근거 앵커
- 추가 검증 필요 사항

# 11. 공용 개념 노트 후보

다음 기준으로 A/B/C를 분류한다.

- A: 이번 강의 안에서 여러 구간에 반복 등장했거나 강사가 일반 원칙이라고 명시한 내용
- B: 한 구간에서만 등장했지만 설명이 명확하고 다른 사례에도 적용 가능한 절차·판단 기준·복구법
- C: 특정 사례에만 해당하거나 근거 부족, 화면 확인 필요, 일반화하기 어려운 내용

A와 B만 독립 개념 노트 후보로 제안한다.
C는 해당 주제 기록에 남긴다.

각 후보마다 다음을 작성한다.

- 개념명
- 등급
- 한 문장 정의
- 적용 상황
- 적용 조건
- 예외
- 관련 절차
- 관련 실수
- 근거 주제·앵커
- 추가 검증 사항

이번 한 강의만으로 A 또는 B를 `standard`라고 확정하지 않는다.

# 12. 실수·복구 표

| 실수 | 증상 | 강의에서 설명한 원인 | 예방 | 강의에서 설명한 복구 | 적용 범위 | 근거 |
|---|---|---|---|---|---|---|

강의에서 원인이나 복구법을 설명하지 않았다면 `확인되지 않음`으로 표시한다.

# 13. 화면 확인 필요 구간

각 항목마다 다음을 작성한다.

- 확인할 내용
- 관련 주제
- 확인된 시작 시각
- 원문 앵커
- 화면에서 확인해야 하는 이유
- 확인 후 기록할 항목

# 14. 용어 교정 후보

| 원문 표기 | 교정 후보 | 문맥 | 확실성 | 추가 확인 방법 |
|---|---|---|---|---|

원문을 삭제하거나 교정 후보로 덮어쓰지 않는다.

# 15. 직접 따라 할 체크리스트

- [ ] 완료 검수

# 16. 복습 질문

# 17. 근거 부족·추가 확인

다음 항목을 모아서 기록한다.

- 주제 경계 불확실
- 전문용어 불확실
- 수치·설정값 불확실
- 시간 정보 없음
- 화면 확인 필요
- 강사의 직접 설명과 분석 후보 구분 필요
- 원문만으로 판단할 수 없는 내용
- 다음 강의 또는 다른 자료에서 재검증할 내용
