# NotebookLM CG Omnibus Feedback Lecture Analysis Prompt

선택된 이번 강의 소스 1개만 근거로 분석해줘.

다른 날짜의 강의, 선택되지 않은 소스, NotebookLM의 기존 대화,
외부 지식을 섞지 마.

## 강의 정보

- 과정명: [과정명]
- 강의일: [YYYY-MM-DD]
- 강사: [강사명]
- 강의 분야: CG 캐릭터 제작
- 강의 성격: 여러 학생의 작업을 순서대로 피드백하는 옴니버스형 수업
- 주요 사용 프로그램: [3ds Max / ZBrush / Substance 3D Painter / 기타]
- 원본 영상 또는 YouTube 링크: [URL 또는 없음]
- 자막 존재 여부: [있음 / 없음]
- 추가 자료: [NotebookLM 소스 / 이미지 / 메모 / 없음]

## 최종 목적

이 분석은 자막 또는 원문과 대조한 뒤 Obsidian의 다음 네 층에 누적한다.

1. 강의 기록
2. 학생별 사례
3. 공용 개념
4. 캐릭터 제작 단계별 워크플로우

단순한 강의 요약이 아니라 다음 작업에 재사용할 수 있는
캐릭터 제작 지식베이스를 만드는 것이 목적이다.

## 중요 규칙

1. 선택된 이번 강의 소스에서 확인되지 않은 정보는 추측하지 않는다.
2. 다른 날짜 강의나 외부 CG 지식으로 내용을 보충하지 않는다.
3. 실제 시간을 알 수 없으면 타임스탬프를 만들지 않는다.
4. NotebookLM의 발췌 번호를 영상 타임스탬프로 해석하지 않는다.
5. 각 세션의 시작·끝 앵커 문장을 원문 그대로 5~15어절 적는다.
6. 앵커 문장은 해당 학생이나 주제로 전환되는 지점을 찾을 수 있어야 한다.
7. 학생 이름이 불확실하면 후보 이름과 불확실성을 표시한다.
8. 같은 학생이 강의 중 여러 번 등장하면 세션을 각각 기록한다.
9. 동일 학생으로 보이면 `동일 학생 후보`라고 표시하되 확정하지 않는다.
10. 개인에게만 해당하는 형태 수정과 다른 작업에도 적용 가능한 원칙을 분리한다.
11. 작업 내용을 캐릭터 제작 파이프라인 단계 중 하나로 분류한다.
12. 단계가 불확실하거나 여러 단계에 걸치면 후보를 복수로 적는다.
13. 단축키·설정값·수치·도구명이 불확실하면 `불확실`로 표시한다.
14. 화면으로만 확인 가능한 조작과 결과는 `화면 확인 필요`로 표시한다.
15. AI 음성인식 오류로 보이는 CG 전문용어는 원문과 교정 후보를 함께 적는다.
16. 교정 후보를 원문 대신 확정적으로 사용하지 않는다.
17. 강사가 명시하지 않은 작업 순서나 원인을 만들어내지 않는다.
18. 해당 내용이 없는 항목은 억지로 채우지 말고 `확인되지 않음`으로 표시한다.
19. 일반화 후보에는 반드시 근거가 된 학생 세션 또는 앵커를 연결한다.
20. 이번 한 강의만으로 절차나 원칙을 `standard`라고 확정하지 않는다.
21. 학생의 사적인 정보나 수업과 무관한 대화는 지식 노트 후보에서 제외한다.
22. 강사의 평가와 분석자의 해석을 구분한다.
23. 분석자의 해석이 포함되면 `분석 후보`라고 표시한다.
24. 화면에서 확인하지 못한 모델 형태와 작업 결과를 단정하지 않는다.

# 2. 학생별 세션 전환표

| 순서 | 학생/대상 | 이름 확실성 | 현재 제작 단계 | 주요 주제 | 시작 앵커 | 끝 앵커 |
|---|---|---|---|---|---|---|

작성 규칙:

- 학생 이름을 알 수 없으면 `학생 A`, `학생 B`처럼 임시 표기한다.
- 같은 학생이 다시 등장하면 `학생 A-2`처럼 별도 세션으로 기록한다.
- 동일 학생으로 보이지만 확실하지 않으면 `학생 A와 동일 후보`라고 표시한다.
- 시작·끝 앵커는 소스 원문 그대로 적는다.
- 정확한 시간이 소스에 없으면 시간을 만들지 않는다.

# 13. 복습 질문

다음 유형을 구분해 작성한다.

## 사실 확인 질문

강의에서 직접 말한 기능, 도구, 설정, 작업 상태를 확인한다.

## 절차 순서 질문

작업의 선행 조건과 실제 순서를 확인한다.

## 원인·결과 질문

특정 형태나 기술적 문제가 왜 발생했고 어떤 결과를 만드는지 확인한다.

## 실수 복구 질문

문제가 발생했을 때 증상, 원인, 예방, 복구 순서를 확인한다.

## 단계 판단 질문

해당 작업이 캐릭터 제작 파이프라인의 어느 단계에 속하는지 확인한다.

각 질문에는 정답의 근거가 되는 학생·세션 또는 앵커를 함께 적는다.

# 14. 근거 부족·추가 확인

다음 항목을 모아서 기록한다.

- 학생 이름 또는 대상 불확실
- 동일 학생 여부 불확실
- 제작 단계 불확실
- 프로그램 또는 기능명 불확실
- CG 전문용어 불확실
- 단축키 불확실
- 수치·설정값 불확실
- 화면 확인 필요
- 원문만으로 판단할 수 없는 형태 문제
- 원인과 복구법이 확인되지 않은 문제
- 다른 강의에서 반복 여부를 확인해야 하는 원칙
- 다음 수업에서 재검증할 내용

# 15. Obsidian 누적 후보

분석 결과를 다음 네 층 중 어디에 저장할지 제안한다.

| 내용 | 저장 층 | 파일 또는 노트 후보 | 상태 | 근거 |
|---|---|---|---|---|

저장 층은 다음 중 하나를 사용한다.

- 강의 기록
- 학생별 사례
- 공용 개념
- 캐릭터 제작 워크플로우

상태는 다음 중 하나를 사용한다.

- case
- recurring 가능성
- principle 가능성
- 추가 확인
- 화면 확인 필요

이번 한 강의만으로 `standard` 상태를 부여하지 않는다.
