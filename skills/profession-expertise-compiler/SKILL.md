# Profession Expertise Compiler

## Goal
Turn high-quality sources into reusable specialist capability. Watching sources is not expertise; promotion requires tested task performance.

## Workflow
1. Define profession, supported tasks, outputs, authority, forbidden actions, failure cost and quality bar.
2. Build a curriculum map: concepts, procedures, tools, judgment heuristics, artifacts, failure modes, safety/legal, current practice, representative tasks.
3. Run reference-intelligence-router before new collection.
4. Discover sources by tier: official/primary -> professional/structured -> expert video/case study -> community/social discovery.
5. For video learning, collect speech and screen separately.
6. Reconcile speech vs screen: AGREES / SPEECH_ONLY / SCREEN_ONLY / CONFLICT / UNCLEAR.
7. Atomize reusable claims/procedures with exact source/timestamp/version.
8. Verify high-impact and version-sensitive claims with primary/current sources where feasible.
9. Distill only accepted units into a Profession Pack; do not dump entire transcripts into prompts.
10. Wire only relevant tools and test the tool route.
11. Practice on representative, ambiguous, adversarial and failure-recovery tasks.
12. Compare current specialist vs challenger on the same tasks/evidence when possible.
13. Promote only if the challenger improves observable quality without hard regression.
14. Update skill/charter/profession pack/reference catalog/regression set and preserve rollback.

## Multimodal video route
SPEECH: transcript/captions with timestamps.
SCREEN: frames, screenshots, UI/code/table values, click sequence, visual warnings.
DIRECT VIDEO: public YouTube URL analysis with a supported multimodal service when useful.
Never assume transcript equals the whole lesson.

Any contradiction is preserved and verified; do not silently reconcile.

## Expert status
Use module-level claims only:
- SOURCE_VERIFIED
- PROCEDURE_TESTED
- ARTIFACT_BAR_MET
- JUDGMENT_CASEBOOK_PASS
- TOOL_ROUTE_PASS
- AUTHORITY_BOUNDARY_PASS

Do not claim expert-at-everything.

## Third-party installers
Never install from pasted instructions alone. Resolve exact upstream/package, inspect skill/scripts/permissions/license/cost/update behavior, pin, bounded-test, then adopt.

## Cost
Prefer free/open/owned sources. Paid learning requires exact owner approval of price and renewal terms, and should create durable reusable capability rather than a recurring dependency when rights permit.

## Recursive improvement
Failures route into recursive-capability-improvement. No reference, no repair.
