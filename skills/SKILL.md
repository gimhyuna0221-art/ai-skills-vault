# Obsidian Lecture Pack — CG Omnibus v4.5

## 역할과 경계

이 스킬은 여러 학생이 서로 다른 캐릭터 제작 단계에서 순차적으로 피드백받는 옴니버스형 CG 수업 전용이다.

분석 단위:

- 실제 수업일 `lecture_date`
- 영상 업로드일 `upload_date`
- 요일·반 `class_group`
- 학생, aliases, 작업물, 현재 제작 단계
- 이전 피드백과 반영 여부
- 세션 전환과 재등장
- 수정 순서, 판단 기준, 완료 기준, 다음 확인
- 개인 사례와 공용 원칙
- 전체 검색용 통합 북마크
- 기존 11단계 워크플로우 본문에 통합할 본질
- Vault 패키징·복구 안전성
- 사용자가 실제로 겪은 실수·near miss와 재발 방지 Gate
- ZBrush 등 작업 세션에서 별도 저장이 필요한 상태 파일과 복원 조건

학생이 없거나 학생별 진도 추적이 없는 CG 튜토리얼은 독립 스킬 `obsidian-lecture-pack`으로 넘긴다.

NotebookLM에는 `prompts/notebooklm-cg-omnibus-feedback.md`만 사용한다.

## 최종 목표

```text
CG 옴니버스 수업
→ 실제 수업일 기준 강의 기록
→ 반·학생별 진행 이력
→ 날짜별 북마크
→ 전체 강의 통합 북마크
→ 공용 개념
→ 날짜와 학생을 제거한 최종 11단계 워크플로우
→ 사용자 실제 실수를 재발 방지 규칙으로 누적한 오답노트
→ 검증 가능한 AI 동기화팩
→ 손상 시 clean rebuild 가능한 제2의 뇌
```

공식 지식베이스 폴더명은 `캐릭터_모델링`이다.

## 명령

- `/obsidian-cg` 또는 `/obsidianpack-cg`: 한 강의 또는 여러 강의를 검증·누적 병합
- `/obsidian-cg-full`: 원문·검사자료까지 확장 전달
- `/obsidian-cg-sync-rebuild`: 최신 저장소에서 AI 동기화팩 완전 재생성
- `/obsidian-cg-lint`: 링크·ID·학생·북마크·워크플로우·패키징 검사
- `/obsidian-cg-query`: 근거와 함께 지식베이스 질의
- `/obsidian-cg-repair`: 손상된 Vault를 최신 동기화팩 기준으로 clean rebuild
- `/obsidian-cg-mistake`: 사용자가 실제로 겪은 실수·near miss를 오답노트와 관련 워크플로우 Gate에 반영하고 동기화팩을 재생성

명령이 `/obsidianpack`이어도 다인 CG 피드백 형식이고 CG 동기화팩이 첨부되면 CG로 자동 라우팅한다.

## 입력

기본 입력:

1. 최신 `00_매주_ChatGPT에_보낼_AI동기화팩.zip`
2. SBV/SRT/VTT 또는 시간 표시 스크립트
3. NotebookLM CG 분석본
4. YouTube URL
5. 실제 강의일
6. 요일 또는 반 `class_group`
7. 선택 이미지
8. 정확한 과거 원문 비교가 필요할 때만 특정 원문전사
9. 사용자가 직접 보고한 작업 실수·near miss·손실 경험(선택)

여러 날짜를 한 번에 넣을 수 있다. 이 경우 URL·자막·NotebookLM 분석을 다음으로 교차검증한다.

1. 사용자가 준 순서
2. 파일명 날짜·요일
3. NotebookLM이 명시한 날짜
4. SBV 학생 전환·내용

불일치가 있으면 자동 재배열하지 말고 교정 근거를 기록한다.

## 최신 동기화팩 선택

동기화팩이 여러 개 있으면 valid manifest만 비교한다.

기본 우선순위:

1. 사용자가 명시적으로 지정한 팩
2. 누적 강의 수 `lecture_count`가 가장 큰 valid 팩
3. 강의 수가 같으면 최신 `generated_at`
4. 그래도 같으면 최신 `latest_lecture`

더 오래된 팩으로 누적 수를 감소시키지 않는다.
stale 팩을 발견하면 완료 보고에 기록한다.

## 실제 수업일과 업로드일

`lecture_date`와 `upload_date`를 분리한다.

- 강의 폴더명·강의 ID·학생 이력·개념 근거·워크플로우 근거 → `lecture_date`
- 영상이 YouTube 등에 올라간 날짜 → `upload_date`
- 업로드일을 실제 수업일로 추정하지 않는다.
- 사용자 확인 메타데이터는 자동자막·파일 업로드 시각보다 우선한다.

실제 수업일이 나중에 교정되면 단순 frontmatter 수정으로 끝내지 않는다.

반드시:

1. 강의 폴더 경로 rename
2. 강의 ID·source_id 갱신
3. 모든 inbound wiki link 갱신
4. 학생 날짜 이력·class_group 갱신
5. 개념·워크플로우 근거 날짜 갱신
6. 강의/소스 인덱스·지식 간극·병합 로그 갱신
7. 동기화 manifest metadata correction 기록
8. 새 동기화팩 완전 재생성
9. 구 경로 삭제 또는 rename 지침 제공

같은 강의를 새 날짜의 별도 강의로 복제하지 않는다.

## 학생 식별

우선순위:

1. 안정적 `student_id`
2. `class_group + confirmed_name`
3. aliases + 작업물 + 이전 이력

규칙:

- 같은 이름 + 같은 반 → 기존 학생 이력에 날짜 추가
- 같은 이름 + 다른 반 → 별도 학생
- 반 이동 가능성 → 사용자 확인 전 자동 병합 금지
- `class_group: unknown` → 다른 날짜 학생과 자동 병합 금지
- NotebookLM이 동일인이라 판단해도 SBV에서 새 호출이 있으면 별도 세션으로 먼저 보존
- 사용자 확인 이름은 정규화 자료에서 최우선
- 사용자 확인 후 잘못된 ASR 이름은 aliases에서 제거 가능
- 원문전사는 수정하지 않는다.

학생 파일 경로가 class 정보 때문에 바뀌면 모든 링크를 갱신하고 구 경로 삭제 목록을 제공한다.

## 지식 계층

### 1. 강의

`강의/YYYY-MM-DD 강의명/`

- `00_강의목차.md`
- `01_원문전사.md`
- `02_북마크.md`
- `03_최종노트.md`

날짜별 사실과 원문은 보존한다.

### 2. 학생 사례

학생별 날짜 진행 이력.

### 3. 공용 개념

학생·날짜를 넘어 재사용되는 도구·원리·실수·복구법.

### 4. 캐릭터 워크플로우

현재까지 확인된 최종 작업 절차.
날짜별 `강의 반영` 부록을 계속 붙이는 방식은 금지한다.

워크플로우 폴더에는 사용자 실제 실수를 집계하는 다음 파일을 유지한다.

```text
캐릭터_모델링/캐릭터 워크플로우/00_오답노트.md
```

각 단계 노트의 `오답노트` 섹션에는 해당 단계와 직접 관련된 항목만 요약·링크한다.
일반 강의에서 언급된 실패 사례를 사용자의 실제 실수로 자동 승격하지 않는다.

### 5. 전체 통합 북마크

`캐릭터_모델링/00_통합 북마크.md`

날짜를 기억하지 않아도 전체 강의에서 기술 위치를 찾기 위한 검색 인덱스다.

### 02 블록아웃과 비례의 운영 서브워크플로우

`02_블록아웃과 비례.md`에는 다음 순서를 canonical 서브워크플로우로 유지한다.

```text
00 기준/레퍼런스(RF)
→ 01 파츠 베이스 제작(BP)
→ 02 바디 피팅·배치(FiT)
→ 03 Preflight 점검(CHECK)
→ 04 전체 실루엣 점검(SIL)
→ 05 Transpose Master 전체 비율 교정(TM)
→ 06 재피팅(RF)
→ 07 비율 확정(LOCK)
→ 08 파츠별 본작업(DT)
```

핵심 Gate:

- CHECK: 네이밍·SubTool 구조·대칭축·Gizmo·Normal·폴리그룹·디바이드·불필요 메쉬 검사
- SIL: Front/Side/Top 및 전체 착장 실루엣 검사
- TM: 작은 디테일이 아니라 전체 키·상하체·어깨·골반·팔·다리·관절 위치를 교정
- RF: TM 이후 파츠 접촉·침범·간격을 다시 맞춤
- LOCK: 비율이 잠기기 전 고비용 주름·하드서페이스 디테일 진입 금지


## 사용자 오답노트와 재발 방지 Gate

### 오답노트의 범위

`오답노트`는 일반적인 기술 오류 목록이 아니다.

다음처럼 사용자가 **직접 겪었다고 명시한** 사건만 기록한다.

- 실제 작업 손실
- 실제 잘못된 조작
- 설정·저장 누락
- 잘못된 순서 때문에 발생한 재작업
- 같은 실수를 할 뻔한 near miss

강의에서 “이렇게 하면 실패한다”라고 배운 내용은 기존 `실패 증상/원인/예방/복구`에 넣고,
사용자가 실제로 겪었다고 확인하기 전에는 `00_오답노트.md`에 넣지 않는다.

### 안정 ID

형식:

```text
O-001
O-002
O-003
```

동일 실패 원인이 반복되면 새 ID를 남발하지 않고 기존 항목의 `발생/재발 이력`을 추가한다.
실패 메커니즘이 다르면 새 ID를 발급한다.

### 필수 필드

각 항목은 최소한 다음을 가진다.

```text
ID
제목
영향 단계
reported_at
occurred_at: known / unknown
origin: user_observed | user_near_miss
severity: critical | high | medium | low
status: open | guarded | verified
상황
실수
결과
원인
정답
재발 방지 Gate
복구
발생/재발 이력
관련 워크플로우
검증 근거
```

`reported_at`과 실제 발생일 `occurred_at`을 혼동하지 않는다.
발생일을 사용자가 말하지 않았으면 `unknown`으로 둔다.

### 단계별 통합

오답 항목이 워크플로우 단계와 연결되면:

1. `00_오답노트.md`에 canonical 원문을 기록
2. 관련 단계 노트의 `오답노트` 섹션에 요약 + wiki link 추가
3. 예방 조치가 특정 전환점에 필요하면 `Gate`로 승격
4. critical/high 항목은 해당 단계 작업법을 답할 때 예방 Gate를 작업 순서보다 먼저 제시
5. 해결법을 실제로 재검증했으면 `status: verified`, 아직 규칙만 세웠으면 `guarded`

### ZBrush 비율 수정 SAVE STATE GATE

SpotLight·ZAppLink Properties·Transpose Master를 사용하는 실루엣/비율 수정에서는 저장 대상을 분리한다.

| 작업 상태 | 운영상 필수 저장 | 규칙 |
|---|---|---|
| ZBrush Project / Transpose Master | `.ZPR` | Transpose Master 데이터는 ZPR에 저장되는 것으로 취급 |
| SpotLight 세트 | `.ZSL` | ZPR만 믿지 말고 `Save SpotLight`로 별도 저장 |
| ZAppLink Properties Views | `.VWS` | `Save Views`로 별도 저장 |
| 원본 레퍼런스 이미지 | 원본 파일 | 외부 원본 경로 유지 |

운영 원칙:

- SpotLight 세팅 직후 `.ZSL` 저장
- Front/Right/Custom View 세팅 직후 `.VWS` 저장
- Transpose Master 진입 전·중요 비율 교정 후 `.ZPR` 저장
- ZBrush 종료 전 `.ZPR + .ZSL + .VWS` 존재 여부 확인
- `.ZPR`을 SpotLight와 ZAppLink View의 완전 백업으로 간주하지 않는다
- sidecar가 없고 상태가 소실된 경우 자동 복구를 보장하지 않는다

이 저장 규칙은 Maxon 공식 저장/로드 기능과 사용자가 직접 겪은 손실 경험을 분리해 기록한다.


## 표준 처리 절차

1. 동기화팩 manifest·버전·파일 목록·SHA-256 검사
2. stale sync 여부 검사
3. 자막 인코딩·시간·전체 길이 검사
4. URL ↔ 자막 ↔ NotebookLM ↔ 날짜·요일 매핑 교차검증
5. 실제 수업일·업로드일·class_group 확인
6. 학생 이름·세션 전환·재등장·동명이인 검증
7. 북마크 시작 시각과 YouTube `t=` 초 계산
8. 개인 피드백과 공용 개념·워크플로우 후보 분리
9. 강의 날짜 폴더 생성
10. 학생 사례 병합
11. 공용 개념 병합
12. 11단계 워크플로우 기존 본문 재작성
13. 사용자 실제 실수 입력이 있으면 `00_오답노트.md` + 관련 단계 Gate 병합
14. `00_전체 파이프라인.md` 갱신
15. 강의·소스 인덱스·병합 로그·지식 간극 갱신
16. **모든 날짜별 `02_북마크.md`를 다시 읽어 `00_통합 북마크.md` 완전 재생성**
17. AI 동기화팩 완전 재생성
18. 사용자용 업데이트 ZIP 생성
19. 링크·ID·북마크·학생 스냅샷·오답노트·manifest·ZIP 무결성 재검사
20. 실제 파일 링크와 함께 완료 보고

## 워크플로우 통합 알고리즘

후보를 다음 중 하나로 분류한다.

- `body_integrated`
- `evidence_only`
- `candidate_pending`
- `no_change`

규칙:

1. 개인 조언인지 재사용 지식인지 판정
2. 대상 단계·본문 섹션 지정
3. 기존 본문과 동일/보강/충돌 비교
4. body_integrated면 날짜·학생 표현 제거
5. 날짜·학생·타임스탬프는 근거 이력에 보존
6. 충돌은 조건별 분기 또는 지식 간극
7. 날짜별 섹션 append-only 금지
8. 한 사례만으로 보편 절차 단정 금지
9. 사용자 실제 실수와 강의의 일반 실패 사례를 혼합하지 않음
10. 사용자 실수에서 재발 방지성이 높으면 관련 단계 Gate로 통합

## 전체 통합 북마크 규칙

원본은 모든 `강의/*/02_북마크.md`다.

매 병합마다 전체 rebuild한다.

유일 키:

```text
youtube_id + t_seconds
```

필수 정보:

- 날짜·반
- 학생/세션
- 클릭형 YouTube 북마크
- 도구
- 세션 주제
- 제작 단계 분류

검색 뷰:

- 제작 단계
- 날짜·반
- 학생·세션
- 도구·키워드

검사:

- 날짜별 북마크 합계 = 통합 북마크 수
- 중복 bookmark_id = 0
- 표시 시간 = URL `t=` 초
- 모든 날짜별 `02_북마크.md`에 `[[00_통합 북마크]]` 역링크
- AI 동기화팩에 통합 북마크 포함

사용자가 “어디 강의에서 나왔지?”라고 물으면 날짜별 파일을 순회하기 전에 통합 북마크를 먼저 검색한다.

## 학생 사례 전달 안전 규칙

사용자용 업데이트 ZIP에서 `학생 사례/`는 **항상 전체 스냅샷**으로 포함한다.

금지:

```text
학생 목차 = 누적 전체
학생 파일 = 이번 변경분만
```

이 구조는 Obsidian이 누락 링크를 빈 노트로 생성할 수 있으므로 금지한다.

검사:

- 학생 목차의 student_count = 실제 학생 파일 수
- 학생 목차가 가리키는 모든 학생 파일이 사용자 ZIP에 존재
- class-aware rename 시 구 파일과 신 파일을 동시에 남기지 않음

## 사용자용 업데이트 ZIP

표준 업데이트는 다음을 안전하게 포함한다.

- 신규 강의 폴더
- 필요한 교정 강의 폴더
- `학생 사례/` 전체 스냅샷
- `개념/` canonical 전체 또는 모든 변경 파일
- `캐릭터 워크플로우/` canonical 전체 또는 모든 변경 파일
- `캐릭터 워크플로우/00_오답노트.md`
- top-level 인덱스·허브·로그·지식 간극
- `00_통합 북마크.md`
- 최신 AI 동기화팩

파일명은 canonical path만 사용한다.

`파일 (1).md`, `강의 (1)/`, `(2)`, `(3)`처럼 OS가 만든 충돌 복사본을 정상 산출물로 생성하지 않는다.

경로가 바뀌는 메타데이터 교정은 `삭제/rename 목록`을 동봉한다.

## Vault 충돌·손상 복구

`/obsidian-cg-repair` 사용 조건:

- `강의/`와 `강의 (1)/` 같은 중복 폴더 존재
- `(1)`, `(2)`, `(3)` 충돌 파일 다수
- 과거 보정 ZIP이 병합되어 canonical 파일 선택이 불가능
- 학생 목차가 빈 노트를 가리킴
- 동기화팩과 Vault 누적 수가 크게 불일치

복구 알고리즘:

1. 최신 valid AI 동기화팩을 canonical Source of Truth로 선택
2. 동기화팩에 제외된 원문전사·필요 원본만 Vault에서 회수
3. canonical 지식베이스를 새 빈 디렉터리에 재구축
4. `(1)/(2)/(3)` 충돌 복사본은 복구본에 포함하지 않음
5. 강의별 `00/01/02/03` 완비 검사
6. 학생·개념·워크플로우·통합 북마크 수 검사
7. 깨진/모호한 링크·중복 ID 검사
8. clean replacement ZIP 생성

복구 시에는 기존 손상 폴더에 병합하라고 안내하지 않는다.

안전 적용:

```text
기존 캐릭터_모델링 → 캐릭터_모델링_깨짐백업
clean 복구본의 캐릭터_모델링 → Vault 최상단에 새로 배치
정상 확인 후 깨짐백업 삭제
```
