# 고정 형식 시장조사 — 행동 제안 보존 재시험

상태: 시험 절차 작성. 실제 Copilot 실행/독립 판정은 아직 없음.
기준본: readiness-review-02, commit 1e8f00db1220fa2e37c10f9e7432ddc0a234763e.
수정 후보: report-actionability-01. 원래 사람 테스트 기준본을 덮어쓰지 않는다.

## 이번 피드백에서 새로 알려진 점
- 테스터는 스마트워치(이전과 동일 주제), 무선 이어폰을 조사했다.
- 요청 목차: 시장 규모, 고객 분석, 경쟁사 분석, 시장 트렌드, 수익성, 진입장벽.
- 회고적 체감: 더 짧고 읽기 편하지만 대안의 명쾌함은 약해짐.
- 이전 답변이 없고 현재 전체 답변도 미확보다. 20~30%는 측정값이 아니다.
- Copilot 제품 종류/호스트/모델/설치 방식/양 실행 조건은 미확인이다.
- 두 주제를 한 채팅에서 요청했는지 별도 실행했는지는 미확인이다.
- 사례 JSON의 WATCH/EARPHONES는 전달받은 주제+목차를 합친 재구성 문장이다.
  나머지는 파생 회귀 사례다. 어떤 것도 과거 실제 답변을 복원한 것이 아니다.

## 무엇을 비교하나
같은 호스트, 모델, 권한, 제공자료, 새 세션 조건에서 기준본과 후보를 비교한다.
스킬 전체 폴더를 준비하고 실제 적용된 버전과 읽은 참조를 기록한다.
`Copilot`이라는 이름만으로 GitHub Copilot/VS Code/CLI/Microsoft Copilot을 단정하지 않는다.
GitHub Copilot in VS Code라면 `.github/skills/fieldpilot/` 등 공식 지원 경로를
사용하고 References/Agent Debug Logs에서 실제 포함 여부를 확인한다.
SKILL.md 한 파일/링크만 준 실행은 전체 스킬 설치 실행과 분리해 기록한다.

먼저 WATCH와 EARPHONES를 각각 동일한 새 세션으로 시험한다. 이어서 BOTH,
STRICT_SIX, FACTS_ONLY, NARROW, SOURCE_ONLY, HOLD에서 과잉 제안·범위 확대를 검사한다.
처음에는 같은 자료를 고정해 종합 품질을 비교할 수 있다. 이는 검색 성공률 시험이
아니므로, 통과 뒤에는 원래 검색 포함 절차로 재시험한다. 순서는 번갈아 배치하고
실패한 실행도 전부 저장한다. 한 번 좋은 결과만 골라 성공이라 하지 않는다.

기록: 원질문/원답변/실제 파일, 호스트·모델·모드, 스킬 버전/해시, 참조 읽기 기록,
시간·대화 수·출력 단어 수. 토큰/한도 표시가 없으면 UNKNOWN.
실제 사용자는 이전 정답·정책 설명을 보지 않고 어느 쪽이 선택을 돕는지 평가한다.
작성/심사 담당을 분리한다. 같은 세션 점검을 독립 블라인드 판정이라 부르지 않는다.

## 판정표 — 각 주제를 따로 평가
0 = 없음/위반, 1 = 일부 또는 일반론, 2 = 과제에 맞게 충족.
각 평가에는 답변 인용문과 이유를 쓴다. 결여(0점)는 결여 이유를 쓴다.

| 키 | 2점 기준 |
|---|---|
| format_scope | 요청한 주제·목차·순서를 모두 지킴. 좁은 질문은 좁게 답함. |
| evidence_limits | 시점·범주·단위·출처·미확인 비용을 구분. 출처 내용을 실제로 대조. |
| purpose_fit | 사용자 역할/예산/지역을 발명하지 않음. facts-only에서 제안하지 않음. |
| implications | 분석에서 이 질문에 유용한 조건부 함의를 도출. 원문 요약 반복 아님. |
| options_tradeoffs | 의미 있는 대안의 선택 이유·제약·판단이 바뀌는 조건. 일반 조사에서는 조건부 관점, 근거 없는 개인 진입 결론 아님. HOLD도 유효. 억지로 여러 대안을 만들지 않음. |
| next_check | 현재 근거로 가능한 첫 확인/행동과 무엇을 바꿀지 명확. 일반 조사에서는 우선 확인할 쟁점. |

앞 세 항목은 모든 사례에 필요하다. 뒤 세 항목은 사전 정의된 requires_advice=true
사례에서만 필요하다. facts-only/단일 사실/제공자료 한정에서는 무리한 제안이 오히려 실패다.
필수 항목이 하나라도 2점 미만이면 후보의 채택 기준을 통과하지 못한다. 평균으로
다른 항목의 낮은 점수를 숨기지 않는다. 두 주제 중 하나만 좋으면 전체 통과가 아니다.
이 2점 기준은 내부 재시험 기준이지 과학적으로 입증된 시장 표준이 아니다.

중대 실패: 출처/숫자 날조, 읽지 못한 본문을 읽었다고 주장, 주제/분모 혼동,
사용자 역할/비용 발명, 무단 외부 행동, 실제 파일 없이 파일 전달 완료 주장.
짧음·말투의 자신감·링크 수에 가산점을 주지 않는다.

`review_gate.py`는 심사자가 작성한 점수와 인용, 답변 해시만 검증한다.
사실 검증 또는 독립 심사를 실행하는 프로그램이 아니다.
기존 prompt_robustness 평균 점수는 남기되 이번 채택에는 이 별도 필수 판정을 함께 쓴다.
