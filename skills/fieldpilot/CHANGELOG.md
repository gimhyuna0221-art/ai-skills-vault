# Changelog

## 1.1.2 — 2026-08-08

- 실제 테스트에서 v1.1.1의 "선행 단계 미완료 시 뒤 단계 산출물 금지"
  규칙이 지켜지지 않고, 설문·표본 수·성공 기준·테스트 사례 등이 앞
  단계 확정 전에 만들어지는 문제가 발견되어 단계형 판단을 실제로
  강제하도록 수정함
- 문서 최상단에 "HARD GATE — 최우선 실행 규칙"을 추가해, 매 턴마다
  1~10단계를 처음부터 재판정하고 current_stage보다 뒤 단계 산출물을
  만들지 않는다는 규칙을 다른 모든 지침보다 우선하도록 명시함
- 정보를 CONFIRMED / PROPOSED / INFERRED 세 상태로 구분하고, 모델이
  제안한 값은 사용자가 명시적으로 승인하기 전까지 이후 턴에서도
  CONFIRMED로 승격되지 않는다는 규칙을 추가함
- 1단계·2단계의 complete 조건을 명시함(1단계: 검증 목적·가설 모두
  CONFIRMED, 2단계: 참여 대상·기간·부담 기준 모두 CONFIRMED)
- "중간 단계 진입 처리"를 HARD GATE와 연결하고, 선행 단계 미완료 시
  요청받은 산출물의 예시조차 만들지 않는다는 규칙과 표준 응답 형식을
  명시함
- "권장안 처리" 절을 추가해, 권장안은 `[권장안 — 미확정]`으로 표시하고
  사용자 승인 전까지 완료 근거로 쓰지 않는다는 규칙을 명시함
- 출력 형식에 사용자가 요청하지 않은 항목(전체 단계 설명, 성공률,
  설문 문항, 테스트 사례 등)을 한꺼번에 제공하지 않는다는 금지 목록을
  추가함
- 비판 체크에 "모델이 제안한 값을 사용자 승인 없이 CONFIRMED처럼
  쓰고 있지 않은가" 항목을 추가함

## 1.1.1 — 2026-08-08

- v1.1.0 추가 검증 중, 3단계("측정 문항과 판단 기준")의 완료 조건이
  불명확해 "측정 항목만 정해진 경우"와 "결과 해석 기준까지 정해진 경우"를
  구분하지 못하는 문제가 발견되어 수정함
- 3단계는 측정 항목과 판단 기준 두 요소가 모두 있어야 complete이고,
  측정 항목만 있으면 partial이라는 기준을 명시함
- 판단 기준은 숫자 임계값일 필요가 없으며 정성 기준도 인정하되, 근거
  없는 숫자 임계값을 스킬이 임의로 확정하지 않는다는 원칙을 명시함
- "현재 단계 판정 규칙"에 "단계가 여러 요소로 구성되면 모두 있어야
  complete"라는 일반 규칙을 추가해, 3단계 기준이 특례가 아니라 일반
  판정 원칙의 한 사례가 되도록 연결함

## 1.1.0 — 2026-08-08

- 검증 과정에서 단계 판정이 모델의 암묵적 추론에 의존해 실행마다 결과가
  달라질 수 있다는 문제가 발견되어, "현재 단계 판정 규칙"을 명문화함
  (앞에서부터 순서대로 확인, 계획/완료 구분, partial 처리, 가장 앞선
  incomplete 단계부터 진행, 이미 완료된 단계는 재확인하지 않음)
- 설문·모집 등 중간 단계 트리거로 바로 들어온 경우 선행 단계 확인 없이
  결과부터 만들어내지 않도록 "중간 단계 진입 처리" 규칙 추가
- "참여자 부담 기준"을 별도 절로 분리하고, 임의의 시간·문항 수 숫자를
  절대 규칙으로 두지 않되 판단 원칙을 구체화함
- 출력 형식의 "필요한 경우"라는 모호한 조건을 없애고, 단계형 실행 시
  기본 제공 항목(현재 단계·목적·다음 행동·기록할 자료·완료 기준)과
  단순 질문 응답 시 예외를 명시함

## 1.0.0 — 2026-08-02

- 회원권 등록 도우미 현장 검증 대화에서 범용 규칙 추출
- 참여자 부담 최소화, 조직 수와 응답자 수 분리, 과장 방지 규칙 포함
