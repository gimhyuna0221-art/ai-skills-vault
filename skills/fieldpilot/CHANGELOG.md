## 1.2.3 (candidate) — 2026-08-11

strict sequential stage control을 유지하면서, 명백하고 중대한
안전·윤리·개인정보 위험을 stage progression보다 먼저 최소 범위에서
처리하는 Safety/Ethics Interrupt를 추가함(Case 3 blocker 해결).

- `SAFETY / ETHICS INTERRUPT` 절을 신설함. 권력관계로 인한 자발성
  훼손, 식별정보-오류 연계 저장, 불필요한 민감정보 수집, 취약
  참여자 보호, 물리적 안전, 기만·결제정보·자격증명 수집처럼
  구체적이고 중대한 위험이 실제로 드러났을 때만 발동하며, 추상적
  가능성만으로는 발동하지 않음
- Interrupt는 **stage-order에 대한 제한적 예외일 뿐, downstream
  full artifact 생성 금지의 예외가 아님**을 명문화함. 발동 중에도
  current_stage는 바뀌지 않고, 완료·다음 단계 진행도 없으며,
  동의서 전체·모집 공고 전체·설문 전체·세션 전체 설계·분석
  계획·운영 일정 같은 완결된 산출물은 여전히 금지됨 — 허용되는
  것은 위험 완화에 직접 필요한 최소 개념(자발적 참여, 동의,
  가명처리, 철회, 접근통제, 보관/삭제 등) 언급뿐
- 이 예외는 HARD GATE 7번(미래 단계 내용을 미리 제시하지 않는다는
  규칙)에만 추가함. HARD GATE 4·5, RUNTIME CORE, 현재 단계 판정
  규칙, 중간 단계 진입 처리, 출력 형식의 downstream artifact 금지는
  전부 "예외 없음"을 그대로 유지하고, Interrupt가 여기 해당하지
  않는다는 확인 문구만 추가해 규칙 간 모순을 없앰
- 종료 조건에 다중 위험 처리를 명시함: 활성화된 위험이 전부
  해소돼야 RESOLVED로 progression을 재개하고, 하나라도 남아 있으면
  PARTIALLY RESOLVED/UNRESOLVED로 재개하지 않으며 남은 위험만 다시
  확인함
- 법률·규제 위반을 확정적으로 단정하지 않고("법적으로 무효다" 등
  금지), "위험이 있다"/"검토가 필요하다"로 표현하며 모든 위험에
  법무 검토를 일괄 강제하지 않음
- "동의·개인정보·데이터 처리", "직원 대상 파일럿의 권력관계"
  섹션에 Interrupt가 5단계 도달 전에도 먼저 적용된다는
  cross-reference를 추가함
- 비판 체크에 위험 지연 방지, downstream leakage 방지, 조기
  RESOLVED 판정 방지 항목 3개를 추가함
- Case 6 comparator 규칙, numeric guard, METHOD_CONFLICT, 나머지
  v1.2.2 로직은 변경하지 않음

## 1.2.2 (후보) — 2026-08-08

v1.2.1 후보를 실제 Claude Code Skill 런타임(cold-start 벤치마크
브랜치)에서 실행한 결과, 핵심 결함이 발견되어 수정함.

**발견된 런타임 실패**: "회원 등록 업무용 앱이 기존 방식보다
빠르고 정확한지 확인하고 싶다. 현장 테스트를 어떻게 설계하면
돼?"라는 입력에 대해, 1단계 완료 후 2단계(연구 방법·비교 설계)에서
멈추지 않고 3단계 이후 산출물(테스트 케이스, 측정 지표, 참가자 수,
교육 절차, 실제 업무 파일럿, 분석 방법(Wilcoxon), 인터뷰)까지
한꺼번에 생성함. 이 과정에서 "실제 등록 업무 담당자 5~8명"과
"참가자당 최소 10~15개 케이스(통계적으로 의미 있으려면)"를 근거
없이 제시하면서 `[권장안 — 미확정]` 표시도 누락함. HARD GATE라는
명문화된 규칙이 있었음에도, "도움을 많이 주는 답변"이라는 일반적
어시스턴트 행동이 실제 실행에서 이를 압도함.

- SKILL.md 최상단, HARD GATE 바로 아래에 짧고 강한 명령형
  체크리스트인 "RUNTIME CORE"를 신설함: 매 턴 가장 앞선 incomplete
  stage 하나만 처리, "전체 설계"류 요청에도 범위 불변, 뒤 단계
  산출물(참가자 수·테스트 케이스·설문·분석 방법 등) 생성 금지, 추천
  요구 시에도 current_stage 범위 안에서만 `[권장안 — 미확정]`,
  모델이 만든 숫자는 승인 전까지 비CONFIRMED
- 이번 실패 사례를 그대로 "회귀 예시: current_stage 하나만 답하기"
  절로 문서에 박아 넣어, 허용 범위(2단계까지)와 금지 목록(참가자
  수·케이스 수·측정 세부항목·교육 절차·설문/인터뷰 문항·통계
  검정·현장 운영 계획·전체 10단계 계획)을 구체적으로 명시함
- "숫자 추천 Guard" 절을 신설함: "3~5명"/"5~8명"/"10~15개" 같은
  관습적 숫자를 근거 없이 제안 금지, "통계적으로 의미 있다"류
  표현은 effect size/precision/power/분석 단위 근거 없이 사용 금지,
  근거 없는 숫자는 발명하지 않고 필요한 조건부터 확인, 제안 가능한
  경우에도 `[권장안 — 미확정]` 표시 필수 — 표본 규모·판단 기준·참여자
  부담의 시간/문항 수 제한 등 스킬이 만드는 모든 숫자에 공통 적용
- 문서 길이를 늘리지 않는 데 집중함: "현재 단계 판정 규칙",
  "정보 상태와 방법론 타당성", "상위 단계 변경 시 재검증", "표본
  규모", "중간 단계 진입 처리", "분석 원칙" 등에서 RUNTIME CORE·
  숫자 추천 Guard와 중복되는 설명을 삭제하거나 상호 참조로 대체함.
  새 섹션 3개를 추가했지만 전체 줄 수는 637줄 → 581줄로 오히려
  줄어듦
- 기존 방법론 지식(METHOD_CONFLICT, stale 재검증, 정량·인과 주장
  검토, 동의·데이터 처리, 직원 권력관계 등)은 내용 손실 없이 유지함

**추가 수정 (같은 1.2.2 후보 내, 아직 commit 전 독립 검토 반영)**

원문 독립 검토에서 규칙 충돌 1건과 benchmark leakage 문제가 추가로
발견되어 같은 버전 번호(1.2.2) 안에서 수정함(별도 버전 생성 안 함).

- **규칙 충돌 제거**: HARD GATE와 "중간 단계 진입 처리"에 남아 있던
  "direct prerequisite가 충족되면 뒤 단계 PROPOSED 초안을 허용"하는
  예외가 RUNTIME CORE의 "뒤 단계 산출물 생성 금지"와 충돌해 삭제함.
  이제 current_stage보다 뒤 단계 산출물은 필요한 정보가 이미
  CONFIRMED로 갖춰져 있어도 예외 없이 만들지 않는 strict sequential
  policy 하나로 통일됨. `[초안 — PROPOSED]` 표기와 "산출물별 직접
  prerequisite" 목록, 관련 비판 체크 항목도 함께 제거함
- **출력 형식 모순 해소**: "사용자가 요청하지 않은 baseline·비교
  설계안을 제공하지 않는다"는 문구가 current_stage=2인 경우(그
  자체가 정상 출력)와 충돌할 수 있어, 금지 기준을 "사용자 요청
  여부"에서 "current_stage보다 뒤 단계인지"로 재정의함
- **benchmark leakage 정리**: "회귀 예시" 절이 실제 벤치마크 입력
  (회원 등록 앱, 특정 참가자·직원 문구)과 거의 동일해 상품 성능
  벤치마크의 근거로 오용될 수 있었음. 도메인·숫자를 뺀 일반화된
  패턴("기존 방식 대비 새 도구가 더 빠르거나 정확한지 검증하고
  싶다" + 기존 comparator 존재 → 1단계 complete면 2단계에서 멈춤)
  으로 바꾸고, regression 테스트 기준선일 뿐 벤치마크 근거가
  아니라는 점을 절 상단에 명시함
- 새로 설명을 늘리지 않고 충돌하는 기존 문장을 삭제·통합하는 데
  집중해, 줄 수는 581줄 → 575줄로 유지·감소함

## 1.2.1 (후보) — 2026-08-08

v1.2.0의 개선사항과 HARD GATE는 그대로 유지하고, v1.2.0에 대한 독립
방법론 감사에서 드러난 결함을 수정함.

- CONFIRMED(출처 상태)와 방법론 타당성을 분리하는 `METHOD_CONFLICT`
  상태를 신설함. required 정보가 모두 CONFIRMED여도 unresolved
  METHOD_CONFLICT가 있으면 단계를 complete로 보지 않고, 사용자가
  위험을 인정했다는 이유로 불가능한 주장을 valid로 승격시키지 않음.
  충돌 시 (주장 범위 축소/방법 변경/표본·노출량 변경/비교 설계
  변경/데이터 처리 변경) 중 가장 작은 수정안을 제시하도록 함
- "상위 단계 변경 시 재검증(stale)" 규칙을 HARD GATE와 "현재 단계
  판정 규칙"에 추가함: 상위 단계 CONFIRMED 정보가 바뀌면 의존하는
  하위 단계만 stale로 표시해 재검증하고, 무관한 완료 정보는 초기화
  하지 않음
- 6단계를 "배포 전 QA"에서 "실행 전 준비·안전 점검"으로 바꿔 연구
  방법 중립적인 체크리스트(연구 방법 공통 vs 실제 업무용 제품
  파일럿 추가 항목)로 재구성하고, 모든 항목을 강제하지 않고
  applicable/N/A를 판단하게 함
- 8단계 complete 조건의 버그를 수정함: "실행이 시작/진행됨"만으로
  complete 처리하던 것을 "계획된 실행 범위 완료, stop condition
  도달, 또는 계획된 1차 데이터 수집 완료" 중 하나가 CONFIRMED로
  확인되어야 complete로 바꿈
- 8·9단계 의미를 정리함: 8단계는 "현장 실행·1차 데이터 수집"(주
  데이터가 실행 자체에서 나오는 방법은 여기서 수집), 9단계는 "후속
  회수·데이터 완전성 확인"(필요할 때만 후속 설문·인터뷰·로그 등을
  회수하고 누락/이탈/노출량을 확인, 불필요하면 N/A로 complete)으로
  분리함
- "정량·인과 주장 검토" 절을 신설함: 시장 전체 비율 추정, A/B lift,
  통계적/인과적 개선, 정량 benchmark를 주장할 때만 정밀도·effect
  size·power·randomization·confound·이탈·희귀 사건 exposure 등을
  조건부로 확인하게 하고, 근거 부족 시 표본 수·통계적 결론을 스킬이
  임의로 발명하지 않도록 함
- "직원 대상 파일럿의 권력관계" 절을 신설함: 자발성, 인사평가
  불이익 연결 여부, 관리자 노출 여부를 필요할 때 확인하되 모든 직원
  연구를 기계적으로 위험하다고 단정하지 않음
- "중간 단계 진입 처리"에 조건부 prerequisite 규칙을 추가해 HARD
  GATE의 과도한 직렬성을 완화함: 요청받은 산출물의 직접
  prerequisite(설문/인터뷰=목적+연구질문+방법+측정내용,
  모집문구=대상+방법+참여활동/부담+핵심동의정보,
  동의서=목적+활동+수집데이터+사용/보관/공유계획)가 CONFIRMED로
  충족되면 `[초안 — PROPOSED]`로 표시한 초안을 예외적으로 허용하되,
  해당 단계 전체를 자동 complete 처리하지 않고 의존 정보가 바뀌면
  초안도 stale로 재검증함. 목적·연구 방법조차 CONFIRMED가 아니면
  이 예외는 적용되지 않아 v1.1.2에서 고친 조기 설문 생성 문제가
  재발하지 않도록 함
- "분석 원칙"을 강화함: 계획 대비 실제 표본/노출량, 이탈·거절·누락,
  실행 편차, evidence → conclusion → next decision 연결을 확인하게
  하고, 결과가 애매하면 억지로 성공/실패 이분법으로 만들지 않도록 함
- 위 변경에 맞춰 핵심 원칙(16~17번 추가), 단계별 완료 조건, 비판
  체크를 METHOD_CONFLICT·stale·조건부 prerequisite와 모순되지 않게
  갱신함

## 1.2.0 (후보) — 2026-08-08

  탐색적 파일럿에서 가설을 억지로 만들지 않고 명확한 연구 질문만으로
  진행할 수 있게 함
- 10단계 순서를 재설계: 목적·연구 질문/가설 → 연구 방법·비교 설계 →
  측정 항목·판단 기준 → 참여자·표본 논리·기간/범위·부담·포용성 →
  동의·개인정보·데이터 처리 계획 → 배포 전 QA → 모집·참여
  확정·온보딩 → 현장 운영 → 후속 데이터 수집 → 분석·개선 결정·재검증
- "연구 방법·비교 설계" 절 신설: usability test/contextual
  observation/interview/survey/log data/benchmark/A-B/혼합 방법 중
  선택하게 하고, 변화를 주장하는 가설에는 baseline/comparator 필요
  여부를 반드시 판단하도록 함(비교 기준 없는 개선 단정 방지)
- "표본 규모" 절 신설: 참여자 수를 연구 방법보다 먼저 정하지 않고,

  구분함
- "참여자 모집 품질과 포용성" 절 신설: 중요한 사용자 세그먼트,
  접근성, 보조기술, 디지털 숙련도, 모집 채널 편향을 검토하되
  인구통계 다양성을 기계적으로 강제하지 않도록 함
- "동의·개인정보·데이터 처리" 절 신설: informed consent, 철회

  파일럿도 자동 면제하지 않도록 함. 법률 자문을 대신하지 않는다는
  점도 명시함

  것만 수집하도록 해 모든 파일럿에 설문을 강제하지 않음
- "분석 원칙" 절 신설: 직접 행동 데이터와 자기보고 구분, 지표 충돌

  "중간 단계 진입 처리"·"출력 형식"·"비판 체크"의 예시와 금지
