# Changelog

## 1.2.1 (후보) — 2026-08-08

v1.2.0의 개선사항과 HARD GATE는 그대로 유지하고, v1.2.0에 대한 독립
방법론 감사에서 드러난 결함을 수정함.

- CONFIRMED(출처 상태)와 방법론 타당성을 분리하는 `METHOD_CONFLICT`
  상태를 신설함. required 정보가 모두 CONFIRMED여도 unresolved
  METHOD_CONFLICT가 있으면 단계를 complete로 보지 않고, 사용자가
  위험을 인정했다는 이유로 불가능한 주장을 valid로 승격시키지 않음.
  충돌 시 (주장 범위 축소/방법 변경/표본·노출량 변경/비교 설계
  변경/데이터 처리 변경) 중 가장 작은 수정안을 제시하도록 함
- "상위 단계 변경 시 재검증(stale)" 규칙을 HARD GATE와 "현재 단계
  판정 규칙"에 추가함: 상위 단계 CONFIRMED 정보가 바뀌면 의존하는
  하위 단계만 stale로 표시해 재검증하고, 무관한 완료 정보는 초기화
  하지 않음
- 6단계를 "배포 전 QA"에서 "실행 전 준비·안전 점검"으로 바꿔 연구
  방법 중립적인 체크리스트(연구 방법 공통 vs 실제 업무용 제품
  파일럿 추가 항목)로 재구성하고, 모든 항목을 강제하지 않고
  applicable/N/A를 판단하게 함
- 8단계 complete 조건의 버그를 수정함: "실행이 시작/진행됨"만으로
  complete 처리하던 것을 "계획된 실행 범위 완료, stop condition
  도달, 또는 계획된 1차 데이터 수집 완료" 중 하나가 CONFIRMED로
  확인되어야 complete로 바꿈
- 8·9단계 의미를 정리함: 8단계는 "현장 실행·1차 데이터 수집"(주
  데이터가 실행 자체에서 나오는 방법은 여기서 수집), 9단계는 "후속
  회수·데이터 완전성 확인"(필요할 때만 후속 설문·인터뷰·로그 등을
  회수하고 누락/이탈/노출량을 확인, 불필요하면 N/A로 complete)으로
  분리함
- "정량·인과 주장 검토" 절을 신설함: 시장 전체 비율 추정, A/B lift,
  통계적/인과적 개선, 정량 benchmark를 주장할 때만 정밀도·effect
  size·power·randomization·confound·이탈·희귀 사건 exposure 등을
  조건부로 확인하게 하고, 근거 부족 시 표본 수·통계적 결론을 스킬이
  임의로 발명하지 않도록 함
- "직원 대상 파일럿의 권력관계" 절을 신설함: 자발성, 인사평가
  불이익 연결 여부, 관리자 노출 여부를 필요할 때 확인하되 모든 직원
  연구를 기계적으로 위험하다고 단정하지 않음
- "중간 단계 진입 처리"에 조건부 prerequisite 규칙을 추가해 HARD
  GATE의 과도한 직렬성을 완화함: 요청받은 산출물의 직접
  prerequisite(설문/인터뷰=목적+연구질문+방법+측정내용,
  모집문구=대상+방법+참여활동/부담+핵심동의정보,
  동의서=목적+활동+수집데이터+사용/보관/공유계획)가 CONFIRMED로
  충족되면 `[초안 — PROPOSED]`로 표시한 초안을 예외적으로 허용하되,
  해당 단계 전체를 자동 complete 처리하지 않고 의존 정보가 바뀌면
  초안도 stale로 재검증함. 목적·연구 방법조차 CONFIRMED가 아니면
  이 예외는 적용되지 않아 v1.1.2에서 고친 조기 설문 생성 문제가
  재발하지 않도록 함
- "분석 원칙"을 강화함: 계획 대비 실제 표본/노출량, 이탈·거절·누락,
  실행 편차, evidence → conclusion → next decision 연결을 확인하게
  하고, 결과가 애매하면 억지로 성공/실패 이분법으로 만들지 않도록 함
- 위 변경에 맞춰 핵심 원칙(16~17번 추가), 단계별 완료 조건, 비판
  체크를 METHOD_CONFLICT·stale·조건부 prerequisite와 모순되지 않게
  갱신함

## 1.2.0 (후보) — 2026-08-08

v1.1.2의 HARD GATE 실행 규칙(CONFIRMED/PROPOSED/INFERRED, 가장 앞선
missing/partial 단계에서 멈추기, 뒤 단계 산출물 선생성 금지 등)은
그대로 유지하고, 방법론 성능 감사에서 드러난 파일럿/사용자 연구
설계상의 구조적 결함을 수정함.

- 1단계를 "검증 목적·가설"에서 "검증 목적·연구 질문/가설"로 바꿔,
  탐색적 파일럿에서 가설을 억지로 만들지 않고 명확한 연구 질문만으로
  진행할 수 있게 함
- 10단계 순서를 재설계: 목적·연구 질문/가설 → 연구 방법·비교 설계 →
  측정 항목·판단 기준 → 참여자·표본 논리·기간/범위·부담·포용성 →
  동의·개인정보·데이터 처리 계획 → 배포 전 QA → 모집·참여
  확정·온보딩 → 현장 운영 → 후속 데이터 수집 → 분석·개선 결정·재검증
- "연구 방법·비교 설계" 절 신설: usability test/contextual
  observation/interview/survey/log data/benchmark/A-B/혼합 방법 중
  선택하게 하고, 변화를 주장하는 가설에는 baseline/comparator 필요
  여부를 반드시 판단하도록 함(비교 기준 없는 개선 단정 방지)
- "표본 규모" 절 신설: 참여자 수를 연구 방법보다 먼저 정하지 않고,
  근거 없이 "3~5명", "5~8명" 같은 고정값을 모든 파일럿의 기본값으로
  제안하지 않도록 함. 정성적 방법과 정량적 방법의 표본 요구를
  구분함
- "참여자 모집 품질과 포용성" 절 신설: 중요한 사용자 세그먼트,
  접근성, 보조기술, 디지털 숙련도, 모집 채널 편향을 검토하되
  인구통계 다양성을 기계적으로 강제하지 않도록 함
- "동의·개인정보·데이터 처리" 절 신설: informed consent, 철회
  가능성, 수집 데이터·목적·접근권한·보관기간·삭제방식, 제3자
  도구·녹화 사용, 익명화를 명시적으로 검토하게 하고, 내부 직원
  파일럿도 자동 면제하지 않도록 함. 법률 자문을 대신하지 않는다는
  점도 명시함
- "설문 회수" 단계를 삭제하고 "후속 데이터 수집"으로 대체: 연구
  방법에 따라 설문·인터뷰·로그·관찰·업무 결과 데이터 중 필요한
  것만 수집하도록 해 모든 파일럿에 설문을 강제하지 않음
- "분석 원칙" 절 신설: 직접 행동 데이터와 자기보고 구분, 지표 충돌
  시 유리한 지표만으로 성공 선언 금지, 희귀 사건을 "미발생"만으로
  해결됐다고 결론짓지 않기, 표본·설계 범위를 넘는 일반화 금지를
  명시함
- 위 변경에 맞춰 "단계별 완료 조건"을 10단계 전체로 확장하고,
  "중간 단계 진입 처리"·"출력 형식"·"비판 체크"의 예시와 금지
  목록을 새 단계 구성과 모순되지 않게 갱신함
- 핵심 원칙에 baseline 판단, 표본 규모 근거, 지표 충돌 처리, 희귀
  사건 결론 금지, 법률 자문 비대행 원칙을 추가함(11~15번)

## 1.1.2 — 2026-08-08

- 실제 테스트에서 v1.1.1의 "선행 단계 미완료 시 뒤 단계 산출물 금지"
  규칙이 지켜지지 않고, 설문·표본 수·성공 기준·테스트 사례 등이 앞
  단계 확정 전에 만들어지는 문제가 발견되어 단계형 판단을 실제로
  강제하도록 수정함
- 문서 최상단에 "HARD GATE — 최우선 실행 규칙"을 추가해, 매 턴마다
  1~10단계를 처음부터 재판정하고 current_stage보다 뒤 단계 산출물을
  만들지 않는다는 규칙을 다른 모든 지침보다 우선하도록 명시함
- 정보를 CONFIRMED / PROPOSED / INFERRED 세 상태로 구분하고, 모델이
  제안한 값은 사용자가 명시적으로 승인하기 전까지 이후 턴에서도
  CONFIRMED로 승격되지 않는다는 규칙을 추가함
- 1단계·2단계의 complete 조건을 명시함(1단계: 검증 목적·가설 모두
  CONFIRMED, 2단계: 참여 대상·기간·부담 기준 모두 CONFIRMED)
- "중간 단계 진입 처리"를 HARD GATE와 연결하고, 선행 단계 미완료 시
  요청받은 산출물의 예시조차 만들지 않는다는 규칙과 표준 응답 형식을
  명시함
- "권장안 처리" 절을 추가해, 권장안은 `[권장안 — 미확정]`으로 표시하고
  사용자 승인 전까지 완료 근거로 쓰지 않는다는 규칙을 명시함
- 출력 형식에 사용자가 요청하지 않은 항목(전체 단계 설명, 성공률,
  설문 문항, 테스트 사례 등)을 한꺼번에 제공하지 않는다는 금지 목록을
  추가함
- 비판 체크에 "모델이 제안한 값을 사용자 승인 없이 CONFIRMED처럼
  쓰고 있지 않은가" 항목을 추가함

## 1.1.1 — 2026-08-08

- v1.1.0 추가 검증 중, 3단계("측정 문항과 판단 기준")의 완료 조건이
  불명확해 "측정 항목만 정해진 경우"와 "결과 해석 기준까지 정해진 경우"를
  구분하지 못하는 문제가 발견되어 수정함
- 3단계는 측정 항목과 판단 기준 두 요소가 모두 있어야 complete이고,
  측정 항목만 있으면 partial이라는 기준을 명시함
- 판단 기준은 숫자 임계값일 필요가 없으며 정성 기준도 인정하되, 근거
  없는 숫자 임계값을 스킬이 임의로 확정하지 않는다는 원칙을 명시함
- "현재 단계 판정 규칙"에 "단계가 여러 요소로 구성되면 모두 있어야
  complete"라는 일반 규칙을 추가해, 3단계 기준이 특례가 아니라 일반
  판정 원칙의 한 사례가 되도록 연결함

## 1.1.0 — 2026-08-08

- 검증 과정에서 단계 판정이 모델의 암묵적 추론에 의존해 실행마다 결과가
  달라질 수 있다는 문제가 발견되어, "현재 단계 판정 규칙"을 명문화함
  (앞에서부터 순서대로 확인, 계획/완료 구분, partial 처리, 가장 앞선
  incomplete 단계부터 진행, 이미 완료된 단계는 재확인하지 않음)
- 설문·모집 등 중간 단계 트리거로 바로 들어온 경우 선행 단계 확인 없이
  결과부터 만들어내지 않도록 "중간 단계 진입 처리" 규칙 추가
- "참여자 부담 기준"을 별도 절로 분리하고, 임의의 시간·문항 수 숫자를
  절대 규칙으로 두지 않되 판단 원칙을 구체화함
- 출력 형식의 "필요한 경우"라는 모호한 조건을 없애고, 단계형 실행 시
  기본 제공 항목(현재 단계·목적·다음 행동·기록할 자료·완료 기준)과
  단순 질문 응답 시 예외를 명시함
