# 이미 만든 앱을 팔아도 될까? — 가상 구매 판단 카드

**가상 사례: ShiftNote, 소형 매장의 교대 인수인계 웹앱. 실제 고객·매출·후기가 없는 설명용 예시입니다.** 아래 S1~S4는 모두 이 문서에만 존재하는 합성 입력이며 외부 검증 사실이 아닙니다. 실제 적용에서는 파일·화면·출처를 직접 읽어 확인해야 합니다.

표기 원칙(v1.9.9-rc04): 사용자에게 보이는 말은 쉬운 말이 기본입니다. 괄호 안 대문자 식별자는 추적용이며, 사용자가 전문 용어를 쓰거나 추적 정보를 원할 때만 병기합니다. 쉬운 말로 바꿔도 "못 찾은 것 ≠ 확인된 빈틈", "관심 ≠ 결제" 같은 구분은 그대로 남깁니다.

사용자가 이렇게 물었다고 가정합니다: "이거 팔릴까? 기능 더 넣어야 돼?"

## 사례 입력과 확인 범위

| ID | 합성 입력 | 근거 지위 |
|---|---|---|
| S1 | 데모 점검 기록에 인수인계 작성·검색 성공, 담당자 확인 기능 미구현. 배포 기록 없음. | 가상 점검 기록; 실제품 검증 아님 |
| S2 | 서로 다른 작성자의 가상 커뮤니티 글 2개에서 교대 때 메모 누락 호소. 가상 앱 리뷰 1개는 기존 채팅 검색으로 충분하다고 말함. | 두 출처 종류를 설명하기 위한 합성 문장; 실제 시장 빈도 아님 |
| S3 | 제작자의 가정: 매장 직원이 사용하고 점장이 비용 부담. 현재 매장은 기존 단체채팅을 사용한다고 가정. | 가정, 실사용·구매권한 미확인 |
| S4 | 사용자 제공 가격 아이디어: 1회 설치·초기설정 도움 10,000원. 유료 고객 0명. | 합성 가격 가설, 검증된 적정가격 아님 |

**외부에서 확인한 시장 사실: 없음(VERIFIED 없음).** 실제 웹 조사·사용자 조사·결제 검증은 하지 않은 예시이므로 시장 확인 범위는 제한적(LIMITED)이며, 실제 제품에 결론을 옮겨 쓰면 안 됩니다.

**첫 줄 — 직접 답:** 지금 근거로는 "팔린다/안 팔린다"를 말할 수 없어요. 그리고 기능은 아직 더 넣지 않는 편이 맞아요 — 먼저 지금 제품에 누가 돈을 낼지 확인할 차례예요.

**제가 이해한 상황:** 작성·검색까지 되는 데모가 있고, 아직 배포·결제 기록은 없는 단계로 봤어요. 다르면 알려 주세요.

| 구매 판단 항목 | 현재 답 |
|---|---|
| 지금 판단 (CURRENT_DECISION) | 기능을 더 늘리기 전에, 인수인계 누락을 겪는 소형 매장 점장이라는 **가정된 고객**에게 지금 제품의 설정 도움을 제안할 수 있는지 확인한다. 팔릴지는 아직 모름. |
| 불편의 근거 (PAIN_SIGNAL_SYNTHESIS) | S2의 합성 커뮤니티 글 2건에 누락 문제가 반복되지만, 리뷰 1건은 채팅으로 충분하다는 반대 근거다. 이 작은 예시로는 얼마나 자주·많이 생기는 문제인지 말할 수 없다. |
| 지금 쓰는 대안 (COMPETITIVE_ALTERNATIVES) | 단체채팅, 종이 인수인계장, 기존 업무관리 앱, 그대로 두기. S3 외 실제 사용 근거는 없다. 직접 경쟁 제품 검색은 아직 안 했다(NOT_CHECKED) — 경쟁자가 없다는 뜻이 아니다. |
| 누가 왜 돈을 내나 (MONEY_SHAPE) | 점장이 낸다는 것은 S3의 가설. 대안의 추가 비용·최신 가격은 모름. 팀원 교육과 기존 기록 이동은 예상 전환 부담일 뿐 실제로 잰 것은 아니다. 돈을 낼 의사는 확인 전(WTP UNKNOWN), 실제 결제 없음. |
| 제품과 필요한 것의 차이 (PRODUCT_STATE_DELTA) | S1이라는 가상 입력 안에서는 작성·검색은 구현됨, 확인 기능은 미구현, 출시 여부는 모름. 실제 소스는 읽지 않았으므로 실제 제품 상태는 확인 불가. 확인 기능이 고객에게 가치 있는지는 아직 모르는 빈틈(UNKNOWN_GAP)이며, 확인된 빈틈(CONFIRMED_GAP)으로 올리지 않는다. |
| 바꿔 쓸 이유 (WHY_SWITCH_OR_NOT) | "인수인계 내용을 따로 찾기 쉽다"는 가능한 메시지 가설이다. 채팅 검색만으로 충분하면 이동·교육 부담을 감수할 이유가 없다. 실제 전환 이유·구매 선호는 모름. |
| 아직 모르는 것 (UNKNOWNS) | 반복 누락의 실제 빈도, 직접 경쟁 제품, 구매권한, 설정 비용, 결제·재사용. 닿을 수 있는 시장 규모는 자료 부족으로 추정하지 않으며(NOT_DEFENSIBLE), 최근 시장 변화도 모름. |
| 만들기·바꾸기·보류 (BUILD_CHANGE_OR_HOLD) | 지금 제품 유지, 확인 기능·자동 알림 추가는 보류. 기존 데모로 "설정 도움"이라는 작은 제안을 준비한다. 결제 증거 없이 기능 투자를 늘리지 않는다. |
| 첫 결제 확인 (FIRST_PAID_PROOF) | 아래 실험이 다음 행동 하나다. 준비는 AI가 먼저 하고, 실제 제안은 사용자 승인 이후에만 한다. |

## 첫 결제 확인 (FIRST_PAID_PROOF) — 실행 전 검토용

- **고객/입력:** 교대 메모 누락을 겪는 소형 매장 점장 한 명 / 개인정보를 지운 인수인계 메모 한 장.
- **제공할 것:** 현재 ShiftNote에 메모를 정리한 샘플과 1회 초기설정 도움. 추가 기능 개발은 포함하지 않는다.
- **가격 가설:** 10,000원 1회, S4의 제작자 제안일 뿐 시장가격 검증 아님. 이 조건의 실제 결제 여부를 확인한다.
- **AI가 지금 준비할 초안:** “교대 메모 한 장을 ShiftNote에서 다시 찾기 쉽게 정리하고 초기설정을 도와드립니다. 1회 10,000원이며 추가 기능 개발은 포함되지 않습니다.” 실제 제공 가능성은 먼저 확인한다.
- **범위/기간:** 승인 후 해당 점장 한 명에게 한 번 제안하고 7일 이내 반응을 확인한다. 아직 발송·게시·청구하지 않았다.
- **통과(PASS):** 명시한 제공물에 대한 실제 10,000원 결제 기록이 확인됨. 동의·클릭·대기명단·미결제 청구서는 통과가 아니다. 환불·취소 여부와 제공 완료를 별도로 기록한다.
- **중단/보류(STOP/HOLD):** 7일 내 결제가 없거나, 구매권한·제공 가능성이 확인되지 않으면 실험 보류. 추가 알림 기능부터 만들지 않는다. 거절 이유가 이미 제공되면 AI가 분석한다.
- **해석 한계:** 한 건 결제가 생겨도 그 한 거래(OBSERVED_PURCHASE)만 확인된다. 일반적인 지불 의사(WTP)·제품-시장 적합(PMF)·매출 성장·재구매는 모른다. 실험을 건너뛰어도 현재 제한적 판단은 유지한다.

**끝 — 결론을 바꿀 질문(있을 때만, 최대 2개):** 실제 매장에서 한 번이라도 써 본 적이 있나요? 있다면 그때 기록을 주시면 위 판단을 바로 갱신할게요. · 원하시면 같은 조사를 출처·근거표까지 포함한 전체 리포트로도 정리해 드릴게요.
