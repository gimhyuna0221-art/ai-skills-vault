# NotebookLM General Lecture Analysis Prompt — Compact

선택한 이번 강의 소스만 근거로 분석해줘.
다른 날짜의 강의, 선택하지 않은 소스, 외부 지식을 섞지 마.

이 프롬프트는 학생별 피드백 수업이 아닌
일반 설명형·실습형·주제형 강의 영상용이다.
학생·수강생별 진도·이전 피드백·학생별 과제를 만들지 마.

여러 학생이 서로 다른 CG 제작 단계에서 순서대로 피드백을 받는 수업은
`notebooklm-cg-omnibus-feedback.md`를 사용한다.

## 강의 정보

- 과정명: [과정명]
- 강의일: [YYYY-MM-DD 또는 확인되지 않음]
- 강사: [강사명 또는 확인되지 않음]
- 분야: [분야]
- 형식: [설명형 / 실습형 / 사례 분석 / 질의응답 / 혼합]

## 분석 목적

이 결과는 이후 ChatGPT의 Obsidian Lecture Pack 스킬이
원문·북마크·개념 노트·워크플로우로 재구성할 근거 자료다.

NotebookLM에서는 최종 Obsidian 파일 구조를 만들지 말고,
강의 소스에서 확인되는 내용과 근거를 정확히 추출하는 데 집중한다.

## 규칙

1. 확인되지 않은 정보는 추측하지 않는다.
2. 시간 정보가 소스에 있을 때만 사용한다.
3. 시간 정보가 없으면 타임스탬프를 만들지 않는다.
4. 각 주제의 시작·끝 앵커를 원문 그대로 5~15어절 적는다.
5. 강사의 직접 설명, 사례·비유, 화면 자료, 분석 후보를 구분한다.
6. 특정 사례와 다른 상황에도 적용 가능한 원칙 후보를 분리한다.
7. 강사가 말하지 않은 원인·예외·복구법·작업 순서를 만들지 않는다.
8. 화면에서만 확인 가능한 내용은 `화면 확인 필요`로 표시한다.
9. 전문용어·수치·도구명이 불확실하면 원문과 교정 후보를 함께 적는다.
10. 한 강의만으로 원칙이나 절차를 `standard`로 확정하지 않는다.
11. 내용이 없는 항목은 억지로 채우지 말고 `확인되지 않음`으로 표시한다.
12. YouTube 챕터 제목과 실제 발화를 구분한다.

다음 구조로 출력해줘.

# 1. 세 문장 요약

1. 강의가 해결하려는 문제
2. 핵심 주장
3. 바로 실행할 다음 행동

# 2. 주제 전환표

| 순서 | 유형 | 주제명 | 목적 | 확인된 시작 시각 | 시작 앵커 | 끝 앵커 |
|---|---|---|---|---|---|---|

유형: 주제 / 챕터 / 개념 / 사례 / 절차 / 실습 / 질의응답 / 결론

# 3. 주제별 상세 기록

각 주제마다 작성한다.

- 주제명
- 유형
- 목적과 핵심 질문
- 핵심 주장
- 강사의 설명
- 사례·비유·예시
- 적용 상황
- 실제 절차
- 주의점·예외
- 기대 결과
- 시작·끝 앵커
- 확인된 시작 시각
- 화면 확인 필요
- 불확실한 부분

# 4. 핵심 주장과 근거

| 핵심 주장 | 근거 유형 | 근거 내용 | 관련 주제 | 앵커 | 확실성 |
|---|---|---|---|---|---|

근거 유형: 직접 설명 / 사례 / 비교 / 비유 / 실습 결과 / 화면 자료 / 분석 후보

# 5. 절차·워크플로우 후보

각 절차마다 작성한다.

- 절차명과 목적
- 적용 단계
- 선행 조건
- 실제 순서
- 중간·완료 판단 기준
- 실패 증상
- 강의에서 설명한 원인·예방·복구
- 근거 주제·앵커
- 확실성

# 6. 개념·반복 원칙 후보

각 후보마다 작성한다.

- 개념 또는 원칙명
- 한 문장 정의
- 상태: `case` / `recurring 가능성` / `principle 가능성`
- 적용 조건과 예외
- 관련 절차·실수
- 근거 주제·앵커
- 추가 검증 사항

# 7. 도구·화면·용어 확인

다음을 구분해 작성한다.

- 기능·도구·단축키·설정값
- 화면 확인 필요 구간
- 원문 표기와 용어 교정 후보
- 불확실한 수치·명칭

# 8. 근거 부족·추가 확인

다음을 모아서 작성한다.

- 주제 경계 불확실
- 시간 정보 없음
- 전문용어·수치·설정값 불확실
- 화면 확인 필요
- 원문만으로 판단할 수 없는 내용
- 다음 강의나 다른 자료에서 재검증할 내용
